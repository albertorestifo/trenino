## Pages, navigation and session boundary

| Browser path | Actual page and initial behavior |
| --- | --- |
| `/consent` | Standalone first-run error-reporting choice; reachable even after a choice exists |
| `/` | Saved hardware configuration list; primary tab is labelled **Devices**, page title **Configurations** |
| `/configurations/new` | Configuration editor's `config_id="new"` branch; immediately creates a persisted `New Configuration` record during mount |
| `/configurations/:config_id` | Existing hardware editor addressed by hardware configuration ID, not database device ID |
| `/trains` | Saved train list, active profile and detected/unconfigured/ambiguous identity state |
| `/trains/new` | Unsaved train form; optional `?identifier=...` prefills identity and suggested display name |
| `/trains/:train_id` | Existing train editor addressed by integer database ID |
| `/trains/:train_id/scripts/new` | Unsaved Lua script form |
| `/trains/:train_id/scripts/:script_id` | Existing script editor, console and manual-run action |
| `/firmware` | Releases, upload wizard and latest ten upload-history entries; `?port=...` can preopen upload |
| `/virtual-joystick` | Standalone offline-capable joystick mappings and Windows runtime lifecycle |
| `/settings` | Error-reporting toggle and simulator connection URL/key configuration |
| `/simulator/config` | HTTP redirect to `/settings` for old links |

The default `live_session` runs ConsentGateHook, NavHook and MCPDetectionHook and uses the app layout. Consent is a separate session without those hooks and its LiveView disables layout. The root document has English language, responsive viewport, CSRF meta, CSS/JS and default title `Trenino` with suffix ` · Phoenix Framework`. No login, account, per-user settings or browser return-to parameter exists. Choice state is application settings; after accepting or declining, the destination is always `/`.

The consent card says “Help improve Trenino”, describes anonymous crash/error reports, no personal data and no usage tracking, and offers **Share error reports** / **No thanks**. Both store an explicit preference and unblock the UI; declining is equally valid. The hook only gates default LiveViews, not API/MCP/health/shutdown endpoints. Each LiveView also installs the Sentry LiveView hook through web macros; actual reporting policy is covered in [operations](desktop-and-operations.md). Evidence: [router](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/router.ex), [consent hook](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/consent_gate_hook.ex), [consent page](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/consent_live.ex), [redirect](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/controllers/redirect_controller.ex), [consent tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/consent_live_test.exs), [gate tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/consent_gate_hook_test.exs).

`PageController.home` and the Phoenix welcome template remain in the tree but are not routed at `/` or another main-router path. Its Phoenix links and visible theme toggle are scaffold residue, not a reachable product home page. `Router.DevRoutes` conditionally defines `/dev/dashboard` when Phoenix LiveDashboard exists, but the main router/endpoint shown here does not forward to it; do not count the module alone as a reachable normal page. ## Shared application chrome and live events

The sticky header contains Trenino/home, **Devices**, **Trains**, **Joystick**, settings (icon-only on narrow screens), and the device count/dropdown. Tabs use the current URI path; Devices includes `/configurations*`, Trains includes nested script pages. Header content generally aligns to a central `max-w-2xl` column; small layouts wrap primary navigation onto a new row. Breadcrumbs connect configuration→list, train→list and script→train→list.

NavHook initializes neutral/empty status without blocking mount, subscribes to serial, simulator, firmware-update and app-version topics when connected, then sends itself `:nav_fetch_initial_state`. It later queries devices, simulator and update state. Device and simulator updates continue through the page's handlers. This delayed fetch prevents UART work from blocking initial page render, but it is still a process message, not an independent worker. [Nav hook](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/nav_hook.ex); [blocked-UART mount tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/nav_hook_test.exs).

| Header state/action | User-visible behavior and event |
| --- | --- |
| Device count | Connected count only: No Devices / 1 Device / n Devices; narrow screen shows numeric count |
| Aggregate status dot | Empty muted; connected green if no discovering devices; connecting/discovering blue pulse takes priority; failed-only warning; otherwise muted |
| Open/close dropdown | `nav_toggle_dropdown`; click-away `nav_close_dropdown` |
| Scan | `nav_scan_devices` calls Connection.scan, sets scanning, disables button and shows Scanning…; `:scan_complete` resets via NavHook |
| Firmware check | `check_firmware_updates` is intercepted by NavHook, triggers background check; checking event changes spinner/disabled state |
| Device row | Port, firmware version if known, capitalized status, per-device status dot, failure reason if present |
| Disconnect | Connected-row X sends `nav_disconnect_device` with port |
| Install Firmware | Offered on failed row only for error types `no_valid_response` or `timeout`; opens `/firmware?port=...` |
| Simulator needs config | Warning banner “Simulator not configured”, Open Settings link |
| Simulator disconnected | Warning “Simulator is offline”, Retry calling simulator retry |
| Simulator error | Error “Simulator connection failed”, Retry |
| Simulator connected/connecting | No simulator banner |
| Joystick page | Suppresses simulator-status banner entirely because its workflow does not need TSW |
| App version update | Info banner with version, external View Release and dismiss (`dismiss_app_version_update`) |
| Firmware update | Primary banner with version, View Update→`/firmware`, dismiss (`dismiss_firmware_update`) |

Dismissals call their update contexts and subsequent PubSub clears the banners. Firmware checking state is displayed in the dropdown; app-version checking has no visible indicator. There is no ordinary primary firmware tab; firmware is reached through banners or failed-device links/direct URL. Evidence: [nav components](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/components/nav_components.ex), [layout](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/components/layouts/app.html.heex), [list/nav tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/configuration_list_live_test.exs).

Each normal page receives the global MCP hardware-detection modal. A `mcp:detection` request displays **Hardware Detection**, an MCP badge, Listening…, the AI-provided prompt and physical interaction instruction. It has a backdrop but no cancel action. Completion clears it without matching the request ID. Late-joining pages receive no replay of an already-running request. Concurrent detections can replace/clear one another's overlay; the MCP description asks clients to run one at a time. The component can label `:simulator`, but only hardware detection is a registered MCP tool. [Hook](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/mcp_detection_hook.ex), [tool](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino/mcp/tools/detection_tools.ex).

## Hardware configuration list and editor

The list loads saved configurations with inputs, renders an empty state with Create Configuration or a card per configuration, and provides New Configuration. Cards show name, optional two-line description, config ID, input count and an **Active** badge when a connected device reports that config ID. Clicking a card opens its editor. This is saved-profile management, not a live-port list. [List source](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/configuration_list_live.ex), [tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/configuration_list_live_test.exs).

### Creating, saving and applying

Entering `/configurations/new` creates the database record before the user types; there is no explicit Create/Save button for the header and no abandoned-draft cleanup. Name/description changes autosave through `validate_device`. The first successful change patches the URL to the actual config ID and exits new mode; errors remain on the form. Existing routes parse ConfigId and redirect home with Invalid configuration ID / Configuration not found if invalid/missing. The patch transition checks that the mounted record's config ID matches or redirects with Configuration mismatch.

The editor has Inputs, Matrices, Outputs, Displays and (existing-mode) Danger Zone. The header shows config ID and Active when matched to a connected port. Apply to Device appears only when at least an input or matrix exists and at least one device is connected; outputs/displays alone do not satisfy this UI gate. Applying disables the action and shows Applying…. The modal lists connected ports and optional versions; selecting a port sends the whole stored configuration to hardware and closes the modal. Acceptance is not completion: the editor waits for configuration-applied/failed PubSub before finishing status.

Explicit apply errors include empty configuration (“Add at least one input”), timeout (“device did not respond”), device rejection, and generic inspected failure at initiation. Successful apply subscribes to that port's values, assigns the returned device/active port, clears applying and flashes Configuration applied successfully. The configuration PubSub subscription is global and the success/failure handlers do not filter device ID/port before updating this editor. Device-update messages discover a newly active port or clear it and current values on disconnect; subscriptions to old ports are not explicitly removed by this page.

Deleting a saved configuration uses a confirmation modal with name and permanence warning for inputs/calibration data. Active configuration disables the Danger Zone button and hides confirm Delete; the domain also rejects `configuration_active`. Success redirects to `/` with the deleted name; failures close the modal and flash a reason. Other input/output/matrix row deletions are immediate and do not use confirmation modals. [Editor source](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/configuration_edit_live.ex), [editor tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/configuration_edit_live_test.exs).

### Inputs and live values

Add Input opens a modal with optional name, Analog/Button type (default Analog), pin, and conditional sensitivity/debounce. Analog sensitivity initializes 5, range 1–10. Button debounce range 0–255 ms is required; the `20` displayed is a placeholder, not a supplied default. The pin input's HTML advertises 0–254, but actual physical input validation is 0–127. Submission inserts through Hardware and shows changeset errors; success closes/reset the form. Cancellation/backdrop closes/reset it. Inputs share unique pins within a device, including across analog/button types.

Rows show pin, editable name (save on blur), type, live value and actions. Offline values are locked N/A; connected but unsampled values show an em dash. Buttons show Pressed for 1, Released for 0. Analog shows raw plus calibrated integer travel if calibration exists, otherwise “uncalibrated”. Analog Calibrate is shown only while active; a forged/inapplicable event flashes Apply configuration to a device before calibrating. Name update/deletion failures flash generic text. [Source](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/configuration_edit_live.ex), [physical pin, debounce and uniqueness tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/configuration_edit_live_test.exs), [hardware details](hardware.md).

### Hardware calibration wizard

Starting calibration subscribes to the input's session and the component starts Hardware.start_calibration_session once. It has pin header, close/backdrop cancel, sample counters, progress indicators and these states:

| State | Instruction/action and condition |
| --- | --- |
| Loading | Starting calibration session… |
| `ready` | Move to minimum; Start enabled before sample collection |
| `collecting_min` | Hold minimum, counters show samples /10 and unique values /3; Next: Sweep enabled only by session `can_advance` |
| `sweeping` | Slowly move min→max, sweep sample count; Next: Set Max (session requires at least ten samples) |
| `collecting_max` | Hold maximum; same 10 sample/3 unique counters; Finish |
| `analyzing` | Spinner, no ordinary step action buttons |
| `complete` | Component has success/failure rendering, while parent completion handlers normally close it and flash result |

Insufficient samples gives Need more samples. Keep the input steady.; insufficient sweep gives Need more movement. Sweep through the full range.; other advancement failures show inspected reason. Cancel stops the session and closes. Session broadcasts (`session_started`, `step_changed`, `sample_collected`) are stored by the parent and passed back into the component so counters update. Save success refreshes input calibrations and flashes Calibration saved successfully; analysis/start failures close with error. These tests mostly exercise the real session/public-state/message flow rather than a complete browser-driven wizard. [Wizard](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/calibration_wizard.ex), [tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/calibration_wizard_test.exs).

### Button matrices and test wizard

Add Matrix accepts comma-separated row and column GPIO pins with 300 ms validation debounce. Parsing trims entries and silently ignores non-integers/partially numeric strings. Requires at least one row and column, range 0–127, no duplicates within each list and no overlap between lists. A live grid previews size and virtual pins `128 + row_index * column_count + column_index`. Submission creates a matrix named Matrix plus virtual button inputs; domain errors appear as general matrix errors. Cancel/backdrop resets both lists/errors.

Rows show editable name, rows×columns, button count, immediate delete and active-only Test. Test opens a visual grid with GPIO labels and virtual pin numbers, totals/percentage, legend, Reset and Close. Never-pressed is muted, currently pressed highlights, tested stays green after release; tested-and-held also rings/scales. Input events for virtual pins >=128 and value 1 accumulate a parent MapSet while testing. Reset clears that set, Close/backdrop hides the wizard. The set persists across reopen unless Reset is used; tracking is not scoped to this matrix's pin range, so unrelated virtual pin events can inflate count. Grid is computed from row/column order, not independent button identity. [Matrix test source](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/matrix_test_wizard.ex), [editor](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/configuration_edit_live.ex), [tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/matrix_test_wizard_test.exs).

### Outputs and physical display setup

Add Output has pin 0–255 and optional name. Validation/save uses Output changeset. Rows allow blur-save name, immediate deletion and active-only test toggle. Toggle sends high/low to the active port and records a local on/off boolean; it ignores the command result and is not actual hardware readback. Initial toggle state is always off in page state.

Displays section lists name, uppercase chip, decimal/hex address, 4/8 digits and brightness percent. Add display is disabled while in new mode until header autosave exits `/new`. Create/edit uses a focus-wrapped dialog with Escape/backdrop cancel, return focus and submit disable text. Fields are optional name, hidden HT16K33 driver, 14-segment letters/numbers or 7-segment numbers, I2C decimal or `0x` address, and 4/8 digits. Advanced settings contain brightness 0–100% (converted to nearest integer 0–15), optional minimum value, right alignment and decimal-point capability. Default hardware params are brightness 8 (~53%), 4 digits, 14-segment, no decimal point, right-aligned, minimum 0.0. Blank minimum means no limit; invalid text remains visible with error; advanced settings open on embedded-param invalidity. Address/name/embedded settings survive ordinary validation and failed save.

Saving refreshes module rows and closes. Delete uses browser `data-confirm` then context deletion and readable failures. Active-only Test writes `8888`, `1234`, `ABCD`, blank (8-character variants for eight digits) at one-second steps. Errors from segment writes are not surfaced; final blank is part of the sequence. [Form](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/components/i2c_module_form_component.ex), [editor](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/configuration_edit_live.ex), [display tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/display_setup_test.exs), [hardware](hardware.md).

## Train list, identity and profile editor

The train list shows saved name, description, **all** identifiers, element count and Active badge. New Train opens an unsaved form. Train detection events update identity/active profile. An unmatched detected ID shows **Train Detected** with Configure→`/trains/new?identifier=...`. Multiple matching profiles show an error banner listing names and all identifiers, saying identifiers must not match more than one profile; there is no manual “pick one” override in this banner. [List](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/train_list_live.ex), [tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/train_list_live_test.exs).

Train editor validates integer path IDs and redirects to `/trains` with Invalid train ID / Train not found. New-mode name is suggested from optional identifier query text. Header has Train Name, optional Description and dynamic identifier rows; all require explicit **Create Train** / **Save**, unlike hardware header autosave. Identifiers use prefix matching, allowing full variant IDs or shorter shared prefixes. Add/remove row dispatches a change; the last row's remove action is disabled and domain rejects saving no identifiers. Duplicate persisted identifier errors appear on fields. Use current train ID is available when connected with a nonempty detected ID; it preserves name/description, replaces a lone blank row, appends if new, and does not duplicate an existing value. Creating calls train detection sync and redirects to the new profile; update stays with Train saved flash.

Existing profiles have Controls, Displays & lights and Automation anchor links. Controls contains elements; Displays & lights groups display bindings then LED outputs; Automation contains a sequences details section (open when nonempty) and script list. Disconnected state warns that simulator configuration/testing needs connection. Active status comes from domain events. Active train deletion is disabled/hides confirm in the UI; inactive deletion confirmation redirects to train list on success. Event handler itself delegates deletion and reports any reason. [Editor](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/train_edit_live.ex), [identity tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/train_edit_live_test.exs), [current-ID tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/display_setup_test.exs).

### Logical elements and readiness

Add Element requires name and Lever/Button (default Lever). Success adds a logical element, resets/closes modal and automatically opens its relevant wizard if a connected simulator client exists. Otherwise it remains unconfigured. Configure Lever/Button events require simulator connected **even for keyboard or sequence button modes**. Delete is immediate (no confirm) and refreshes the list. Wizard completion refreshes elements, reloads LeverController/ButtonController and flashes configuration saved; cancellation closes and clears relevant temporary assignments.

Lever badges: Ready if **any** notch has both input range endpoints; Needs mapping if input-bound; Needs input if lever config exists; Not configured otherwise. Button badges: Ready if a binding has at least one sequence in sequence mode, nonblank keystroke in keystroke mode, or non-nil endpoint otherwise; Partial if binding exists but fails that criterion; Not configured otherwise. These are presence heuristics, not proof that every notch, hardware connection or runtime controller is operational.

### Shared simulator API explorer

API explorer appears embedded in wizards or as its own modal; it starts by listing root. It sorts child nodes and endpoints by name; nodes accept `NodeName` or `Name`, endpoints use Name/Writable. Search is case-insensitive substring matching of the **current node's items only**, with 150 ms keyup debounce. Home and clickable path segments navigate upward. Nodes join with `/`; leaves append `.`. Endpoints show RO/RW. Node names containing `(` use a control-cube icon; other nodes use folder icons.

Clicking endpoint reads a preview; node navigation lists children, then attempts readback for empty/unlistable leaves. Preview displays pretty JSON/map or inspected value and Select This Path. Hover controls allow preview/select directly. Arbitrary node or read-only paths can be selected; the explorer is not a writable-only validator. Initial/list/read errors show an alert (preview-only failures can be silently ignored); empty/search-no-match shows No items found. Close/backdrop sends a parent event; in binding wizards this usually cancels the whole wizard.

In lever mode (or unspecified mode), a node with `Function.GetMinimumInputValue`, `Function.GetMaximumInputValue` and writable `InputValue` shows Lever Control Detected, optional notch-count/index indication, Configure All Endpoints and Choose Individual Endpoints. It builds full paths for required three and optional `Function.GetNotchCount` / `Function.GetCurrentNotchIndex`. In button/unspecified/sequence mode, writable InputValue shows Button Endpoint Found; min/max are fetched if present to suggest off/on, otherwise 0/1. `:none` mode used by output/display suppresses control detection. The explorer does not itself edit simulator values. [Source](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/components/api_explorer_component.ex).

### Shared simulator control auto-detection

Quick Setup's Auto-Detect Control opens a separate component: Ready to Detect→Start Detection→Setting Up…→Listening… with displayed 30-second countdown→one/multiple detected controls, timeout or error. Detected rows show control name, endpoint and previous/current values rounded to two decimals; multiple rows use radios. Use This Control forwards selected result; Detect Another resets/restarts; timeout/error offers Cancel and Try Again. Close/backdrop stops a live session. Named errors include Simulator not connected, Failed to query simulator controls, No controls found to monitor, otherwise inspected reason.

TrainEditLive starts the session and forwards result/timeout/error to the component. Its timer only reschedules when parent `show_auto_detect` is truthy; the actual nested open flags live in components, so the visible countdown is not guaranteed to tick as described. The underlying timeout still delivers. This is UI simulator detection, separate from MCP hardware detection. [Auto-detect component](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/components/auto_detect_component.ex), [parent forwarding](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/train_edit_live.ex).

### Button setup wizard

New button starts **Choose Type** with Simulator Control, Trigger Sequence or Keyboard Key. Simulator route adds **Find Control** (API explorer or auto-detect) before **Configure**. Existing complete bindings start Configure. Sequence/key routes go straight Configure. Close/backdrop cancels. Back goes to type choice for sequence/key or browse for simulator and clears mapping-complete/endpoint state.

Configure includes:

- Hardware Input: no-input instruction; Detect then physical button press; waiting spinner/cancel; detected name/device/pin and Change. Parent subscribes to connected ports for available saved physical and virtual button inputs, resolves config ID+pin, and selects on value 1. No timeout is implemented for this page-level button detector. A `select_input` event also exists but the rendered panel offers detection, not a manual dropdown.
- Binding behavior: simple (send once), momentary (repeat while held), sequence or keystroke; hardware momentary (spring-loaded) or latching (toggle). Repeat interval loads/defaults 100 ms, but no editable repeat-interval control or event is rendered here.
- Sequence: select On Press, plus On Release only for latching; at least one is needed. Empty sequences warns and provides a cancel link labelled Create one in Sequences section (its `#sequences` fragment does not correspond to the current Automation section ID).
- Keyboard: Capture focuses a keyboard target; modifier-only presses are ignored, then CTRL/SHIFT/ALT plus normalized key are sent. Change/Clear/Cancel available. UI describes holding the key while button pressed; actual OS behavior is in [controls](train-profiles-and-controls.md).
- Simulator values: defaults on 1.0/off 0.0; manual float entry rounded two decimals; auto mode can Start Detection, capture resting/off as first sample and detect on after absolute change >0.05, then Retry/Confirm; Detect Again after confirmed. Parent uses reserved simulator subscription ID 999 and polls every 200 ms; stops/unsubscribes on stop message. Detection can run indefinitely if no change. Suggested values from auto-detect use previous/current values; direct detected standard endpoint uses min/max suggestions.

Save enabled conditions: input+any sequence for sequence mode; input+nonblank key for keystroke; input+endpoint for simulator. **Value confirmation is not required** to enable save in simulator mode. Save updates an existing binding or creates one and returns completion; error changesets flash field messages. Joystick destination conflict is not given a special readable branch in this wizard; non-changeset error formats as An error occurred. There is no separate rendered “Test button” execution action despite component naming/comments. ### Lever setup wizard

New flow has six steps: **Lever Type → Select Input → Find in Simulator → Calibration Info → Detect Notches → Map Positions**. Existing partial/full configuration omits Calibration Info (five steps). Old test names/comments calling these five/four omit the newer Lever Type step; implementation arrays govern. Type currently offers only Analog Potentiometer, immediately advancing to Select Input. Only calibrated analog inputs are listed, with device/pin. Continue requires selection. No calibrated inputs gives a warning directing hardware calibration.

Find in Simulator uses lever-mode explorer and displays selected min/max/value paths. Continue needs all three. Configure All Endpoints is the main working auto-fill route. Individual-selection events update endpoint map. The general auto-detect component can open, but the lever result handler only closes it and **does not derive/set endpoints**, so it cannot complete missing endpoint configuration by itself.

Calibration Info explains automated simulator movement and asks for stationary loaded train, free lever/no physics locks, key in/reverser neutral. Start Calibration triggers parent LeverAnalyzer analysis, creating/updating config immediately; this is not an unsaved final-form transaction. Spinner shows Analyzing Lever…, completion shows discrete/continuous/hybrid classification, notch count and gate/linear descriptions/values. Error has readable reason; Back is hidden while running. Entering Detect Notches via edit-mode navigation reruns calibration. `Skip (Manual)` merely switches to Map Positions and does not create manual notches, start a session or create missing config; no manual-notch editor is rendered, so that route can remain at loading.

Map Positions fetches fresh config and requires selected calibrated input plus connected matching port, then binds input, starts a mapping session and begins mapping. Missing config/input/port/calibration/bind/start failures flash a reason. Visualization draws gates as dots and linear spans with equal schematic spacing, a current-notch highlight, captured percentages and click-to-revisit; it is not physical-range-proportional. Although the visualizer can draw a live position line, this wizard intentionally does not pass current_value, so that line is absent. The panel shows current calibrated value; Start Capturing opens min/current/max/sample counts, Reset, Stop, Capture. Gate instruction is wiggle in position; linear instruction sweep full range. Capture enabled comes from session can_capture; errors distinguish no samples, no range, other failure. Once all captured, preview has Save Mapping. Successful session save closes wizard/reloads controller; failed save flashes reason. Direction detection occurs on save in the domain.

Editing uses clickable step indicators and tracks dependencies: changing hardware input invalidates Map Positions; changing min/max/value endpoints invalidates Detect Notches and Map Positions; reverting original values clears these flags. Cannot skip over an earlier invalidated step. Configured steps show green checks, invalidated warning. Leaving mapping cancels its session; cancellation closes wizard but does not roll back config/binding writes already made. “Test live feedback” in comments is not a separate final wizard step. [Lever wizard](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/components/lever_setup_wizard.ex), [visualizer](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/components/lever_visualization.ex), [tests](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/test/trenino_web/live/components/lever_setup_wizard_test.exs), [domain](train-profiles-and-controls.md).

### Sequences and endpoint/value selector

Automation's Sequences component lists name and command count, New Sequence, Edit, Test, browser-confirmed Delete. New modal requires trimmed nonblank name; context validation failure silently stays open. No UI rename field exists after creation. Edit loads ordered command drafts; Add Command defaults endpoint empty/value1.0/delay0, Remove removes locally, fields edit numeric value and delay (HTML min0, step50), endpoint opens selector when a simulator client exists. There is **no reorder control/event**, despite module comment claiming reorder. Save replaces all commands; invalid numeric text parses as 0/0.0 and context enforces remaining constraints; save errors are silent. Cancel discards drafts. Deleting notifies parent to refresh. Test disabled only for zero commands, not disconnected simulator: it spawns execution, tries each current simulator connection, silently skips writes if disconnected/ignores write errors, sleeps each delay, and immediately flashes Testing sequence with no completion report.

EndpointSelector's two steps are Select Endpoint and Configure Value when value detection is enabled (sequence uses it). Browse or simulator auto-detect chooses path; otherwise can select path alone. Configure offers manual float rounded two decimals, or Start Detection waiting→first polled value→Detected→Retry/Confirm. Unlike button ON/OFF, this captures one sample immediately, not a change. Final Confirm requires selected/manual value and sends combined endpoint+value to avoid race conditions; detected auto-control result initially populates detected_value but is not automatically accepted as selected_value. Back returns to browse; cancel closes selector. Parent routes explorer/detection events to active wizard or the sequence selector, and uses the same reserved 999 subscription/200 ms poll. ## Lua script editor

Train Scripts lists name, trigger count, enabled toggle, Edit and browser-confirmed Delete; toggling/deleting explicitly reloads ScriptRunner. Add Script opens its own page. Existing editor independently fetches train and script; it does not check script.train_id equals route train_id. Numeric path conversion can raise on malformed IDs; missing records redirect to `/trains` with Not found/Train not found.

Editor is a monospace textarea (18 rows, resizeable, no syntax-highlighting IDE), name, Create/Save and Back. Default code defines `on_change(event)` and prints source; comments explain source/value/data. Code validates on blur, name/form validates through changeset; save includes trigger draft array. Create/update explicitly reloads ScriptRunner, creates navigate to saved script or stays with saved flash. Failure keeps form and generic create/save flash plus field errors. Enabled toggle exists only after saving and persists immediately; Run exists only after saving, triggers the persisted script ID, flashes Script triggered and refreshes logs once after 300 ms. It does not first save editor drafts or wait for successful execution.

Trigger input trims, ignores blank/duplicate entries and resets input; removable pills preserve order; changes persist on script Save. Empty trigger hint says manual-only. Console exists only for saved scripts, reverses log list for display, colors `[error]` lines, has explicit Refresh and no live subscription. Runner log load errors/exits produce empty console. Hardware Outputs Reference collapses to a table of output ID/name/pin/device and instruction `output.set(id,true/false)`; loaded once at mount. Source [script editor](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/script_edit_live.ex), [train editor](https://github.com/albertorestifo/trenino/blob/188f35e4108733358730e92ebd98f1912af5173a/lib/trenino_web/live/train_edit_live.ex); runtime contract in [scripting](scripting-and-sequences.md).

**Shared-nav limitation:** ScriptEditLive defines no `nav_toggle_dropdown`, scan/disconnect/retry handlers and swallows ordinary handle_info messages. NavHook intercepts its own update/check messages but allows device/simulator messages through; consequently its inherited header can have stale live device/simulator state and normal nav actions may be unhandled. This should be tracked as current behavior, not documented as an end-to-end proven feature on that page.

## Firmware page and upload interaction

Page loads saved releases/files, latest ten history entries, current upload and upload subscriptions. Check for Updates calls release fetch, toggles checking/spinner/disable, then refreshes or flashes inspected failure. No releases shows instruction to check GitHub. Latest release emphasized; older releases collapsed behind Show n older releases. Cards show version/tag/date, board names, Latest and Incompatible badges, external release link. Incompatible Upload disabled with requirement/app-update message.

Upload modal normally resets selected port/type and errors. `?port=...` preselects that port and latest stored release and opens automatically if releases exist; does not pick board. Port options enumerate **all** OS serial ports, annotated with known firmware versions, including ports not connected to Trenino. Board options come from DeviceRegistry, not filtered to release files. No ports shows USB/scan instructions and scan button. Form requires port+board; warns not to disconnect. Start rechecks compatibility, finds matching release file, downloads if not already present, starts Firmware upload, and displays missing-board/incompatible/start failure. Upload PubSub drives percent/message and current job; success clears modal/progress, refreshes history and flashes duration; failure leaves modal/error and refreshes history. Cancel Upload delegates using current upload ID; no current job is a no-op. History shows port, board, Success/Failed/Cancelled/In Progress, duration and start-time-of-day.

While uploading the normal close button/cancel are hidden, but the backdrop still sends close_upload_modal and its handler does not block it; a user can hide an ongoing upload modal without cancelling. There is no progress panel outside that modal, and current-upload mount alone does not automatically reopen it. ## Virtual joystick page

Page loads all mappings and saved physical/virtual inputs, including uncalibrated analogs. On non-Windows **or Windows without the Manager**, mount presents Windows required to activate; MCP distinguishes the latter as runtime unavailable. Runtime updates use joystick PubSub; simulator failures are suppressed in header. Mappings can be edited while hardware disconnected, joystick off, or platform unsupported. Axis/button sections normally show assigned targets only, capacity “n of 8 axes · n of 32 buttons”; Show unused targets reveals all eight axes and buttons1–32.

Add mapping opens Axis/Button choices. Axis form lists only analog inputs; button form only button inputs. Target axes X,Y,Z,Rx,Ry,Rz,Slider1,Slider2; buttons1–32; axis inversion checkbox. Existing mapping locks hardware input and updates destination/inversion. Empty compatible inputs links to hardware setup and disables save. Preview explains connect device/calibrate analog/select/move; matching connected port+pin updates analog normalized percent or Pressed/Released. Preview uses non-inverted normalization regardless of draft inversion. Uncalibrated analog can still be saved even though preview unavailable. Modal uses focus trap/return focus/Escape; delete immediate.

Duplicate target changesets show That joystick target is already assigned. Existing simulator/API destination opens explicit Replace existing binding? with cancel and Replace binding; confirmation calls put_mapping with replace true. Enabling/disabling blocks mapping mutations in both handlers and disabled controls. Regular create/update/delete reload mappings; replacement's handler does not explicitly call reload after success (domain behavior remains relevant).

| Runtime state | Display / available action |
| --- | --- |
| unsupported | Windows required to activate; Windows10/11 message; no toggle |
| off | Off; Enable |
| enabling | Turning on; no toggle/recovery, Windows permission may be cancelled |
| active | On, mapped controls sent to device1; Disable |
| disabling | Turning off/removing device; no action |
| needs_setup | Setup needed, unfinished Windows creation; Retry |
| needs_cleanup | Cleanup needed; Remove leftover device |
| degraded | Connection interrupted, reconnecting; Retry |
| error/driver_missing | Needs attention; repair app installation instruction, Check installation |
| error/incompatible | Needs attention; correct device1 controls, Check configuration |
| other error | Needs attention; Retry |

Toggle opens an enable/disable confirmation explaining Windows administrator permission; Cancel/Escape closes, Continue starts appropriate lifecycle action and closes. Recovery chooses cleanup, repair for missing/incompatible driver, otherwise retry. Returned command errors are ignored at event boundary and eventual status messages are relied on. UAC-cancelled variants explain no change for off/enabling/setup, or restoring without changing Windows for degraded. ## Settings page

Error Reporting toggle persists enabled/disabled immediately and Review consent details returns to consent card. Simulator form has URL, password key override, platform-specific key detection/help and **Save and test connection**. ## Client hooks, styling, accessibility and transient state

`app.js` connects LiveSocket `/live` with CSRF and 2500 ms longpoll fallback, merges colocated hooks and custom hooks, exposes `window.liveSocket`, and uses topbar after 300 ms page-loading start, hides on stop. `phoenix_html` enables method/confirm behavior. In development live reload streams server logs and Ctrl-like held `c`/`d` plus click jumps to caller/component definitions; these are developer conveniences.

AutoDismiss applies only to info flash, defaults5000 ms, fades200 ms then clears info flash/removes node; errors remain until clicked. Both types are clickable clearable top-right alert toasts. Shared flash group shows disconnected client/server notices with Attempting to reconnect, hidden when connected. KeystrokeCapture prevents default propagation, ignores modifier-only keys, collects CTRL→SHIFT→ALT (Meta not encoded), normalizes letters/digits/numpad/function/special navigation keys and emits `keystroke_captured` to target. Listener/timer cleanup happens on hook destruction. ## Evidence and known test limits
