# Rust-backed desktop UI implementation plan

> **For agentic workers:** Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` when implementation is authorized. This document is a planning proposal; no application implementation or passing tests are claimed.

**Goal:** Retain the Tauri desktop application, current screens, styling and workflows with a small TypeScript presentation layer and all application logic in Rust.

**Architecture:** Bundle a static Svelte + TypeScript + Vite frontend under `tauri/ui`. Components render Rust snapshots and send typed intents; Rust owns validation, workflow state machines, persistence, hardware, simulator interactions and execution. No SvelteKit server, SSR, Phoenix connection or localhost UI server is required in the packaged application.

**Tech stack proposal:** Svelte, TypeScript, Vite, existing Tailwind/daisyUI theme definitions and Heroicons, Tauri 2 IPC. Pin versions after the milestone-zero WebView compatibility check; do not upgrade the visual design alongside the rewrite.

**Spec:** [Coordinated rewrite](2026-10-24-rust-rewrite.md), with [platform contracts](2026-10-24-rust-platform.md). Hardware, controls and joystick plans own domain implementations.

## Constraints and review focus

- Keep Windows/Linux desktop packages and macOS source-build portability. Windows-only joystick support must render an unsupported state elsewhere.
- The frontend owns navigation, focus, open panels, selection highlighting, raw draft text and display formatting. Rust owns application rules, including wizard prerequisites and which transitions are legal.
- Keep the wire protocol, external HTTP/MCP interfaces and database identities. UI commands do not use the compatibility HTTP listener.
- Five priority failure classes: a stale validation response replacing a newer draft; concurrent MCP edits during Save; navigation during calibration/flash; a stale MCP completion clearing another prompt; keyboard capture interacting with Escape/focus. Tasks below explicitly cover each.
- Do not convert existing immediate writes into an all-or-nothing form accidentally. Any change to persistence timing is a separately labelled product correction.

## Small frontend boundary and shared IPC contract

Proposed file grouping:

```text
tauri/ui/package.json, package-lock.json, index.html, vite.config.ts, tsconfig.json
tauri/ui/src/main.ts, App.svelte
tauri/ui/src/app/                  routes, shell, navigation, theme, global prompts
tauri/ui/src/components/           presentation primitives only
tauri/ui/src/bridge/               generated.ts, client.ts, subscriptions.ts, errors.ts
tauri/ui/src/features/             hardware, trains, controls, outputs, scripts, firmware, joystick, settings
tauri/ui/src/styles/app.css        retained theme tokens and utility setup
tauri/ui/tests/                    bridge, forms, workflows, visual fixtures
tauri/ui/e2e/                      packaged desktop smoke scenarios
tauri/src-tauri/src/commands/      thin domain command adapters (shared platform ownership)
crates/trenino-core/src/ui/        transport/error/view DTOs, no Tauri dependencies
```

Generate DTO types from Rust or check generated schema fixtures in CI; do not maintain competing handwritten domain types. `bridge/client.ts` is the only feature-facing invoke adapter, with typed functions such as `getConfiguration(configId)`, `validateDraft(kind, draft, draftRevision)`, `saveTrain(draft, expectedRevision)`, `startOperation(kind, args)`, `advanceSession(sessionId, action, expectedRevision)` and `cancelOperation(operationId)`. These names are illustrative until milestone zero aligns them with each domain service; adapters must not invent a second validation implementation.

- Keep `EntityId` as decimal string for DB IDs. **Configuration route `config_id` is a separate public `ConfigId`, not necessarily the row ID.** Preserve its existing parser/format and do not coerce it through JavaScript Number. Use opaque string operation/session IDs. Revisions also need a lossless wire representation if backed by u64.
- Reuse platform `AppError { code, message, field_errors, retryable }`. Field paths identify nested command/identifier rows. A separate typed conflict result supplies current entity revision and replacement candidates; secrets and internal traces never enter field messages.
- Mutations carry expected entity revision and a request identity for operations whose retries could duplicate effects. Rust returns committed snapshot/revision or a conflict. UI does not automatically replay Save/Test/Flash after a lost reply; reconcile the request/operation first.
- Routing views distinguish desired persisted revision from active runtime revision. A successful commit followed by failure to release the previous destination must display saved-but-not-active suspended/degraded status and recovery, never a success badge implying the new route is operating. Activation/release barriers belong in Rust.
- Reuse platform `Snapshot<T> { epoch, topic, revision, value }` / `Change<T> { epoch, topic, revision, value }`. Global revision gaps are meaningless to a filtered subscriber. Use per-topic contiguous delivery revisions, or explicitly signal resync; coalesced telemetry is latest-value and must not falsely trigger a gap alarm. Restart changes epoch and forces resnapshot.
- `subscriptions.ts` subscribes and buffers before requesting snapshot, applies newer matching-stream changes, discards duplicates and handles resync. Shell subscriptions survive route changes; page subscriptions dispose on unmount. Unsubscribe only releases observation, never cancels a running operation implicitly.
- Tauri channels suit ordered per-operation progress; low-rate global notifications may use events. Neither replaces application-level IDs, snapshots or resynchronization. Keep rendering telemetry coalesced; physical button edges/sequence actions never travel through frontend logic.
- Rust session view DTOs expose status, step, legal actions, eligible choices, sample summaries, failures and persisted milestones. Frontend may request Next/Back but cannot authorize progression itself. Debounce validation IPC and tag raw drafts; discard stale validation replies without erasing newer text. Native input hints are supplementary, not authoritative validation.
- Lua editing is text; execution, trigger trimming/deduplication, code checks and logs belong in Rust. Display preview formatting, key normalization, I2C conversion, simulator value rounding, mapping conflicts and timer decisions are application rules, even where they currently live in LiveViews/JavaScript.

## Persistence, cancellation and accessibility behavior

| Current behavior from handlers | Migration contract / separately proposed correction |
|---|---|
| Entering `/configurations/new` immediately calls `Hardware.create_device`; device-name change writes and patches to public config URL. Inputs, outputs, matrices and inline names save individually. | Preserve immediate-create/autosave semantics initially, but make create a single identified intent so rerender/subscription does not create duplicates. Creating only on first Save would be a separately approved correction. |
| New train is an unsaved struct; `save_train` commits. Elements and associated bindings have their own save actions. | Do not create a train merely by opening the route. Keep parent-save prerequisites and separate child commits. |
| Lever calibration/configuration and mapping involve separate services/commits; closing wizard is not a transaction rollback. | Characterize each persisted milestone in controls fixtures. Cancel stops current session/effects, preserves completed commits; show accurate state when reopened. An atomic all-or-nothing wizard is a separate redesign. |
| Sequence Create commits a sequence; command rows remain an editing draft until Save; Test loads saved commands. | Preserve this distinction, including Close discarding only command draft. Rust executes saved sequence; no JS timers. |
| Script Save commits code/triggers; enabled toggle writes immediately; Run Now runs saved script and new scripts must first be saved. | Preserve saved-versus-draft behavior. Manual console refresh remains; adding streaming console is optional and must remain bounded. |
| Settings Save persists URL/key then tests; empty key preserves stored key. Key-status helper describes file detection. | Failure to connect does not undo saved settings. Preserve blank-key semantics; a clear-key action or status combining manual/file sources is a separate correction. |
| Shared modals support backdrop close; joystick form already has focus wrap, Escape and focus restoration; many others do not. | Preserve available interactions and standardize accessible dialog focus/labels as an explicit usability correction. Escape in keyboard capture must be captured as a key unless an explicit Cancel action is used. |

Navigation can discard ordinary local drafts (an unsaved-change prompt is optional product work), but session cancellation must be deliberate: session owner policy stops detection/capture when leaving their workflow and waits for terminal acknowledgement or shows pending cleanup. Firmware upload remains runtime-owned across routes; reopen attaches to its operation. Closing the app follows platform flash policy, not generic modal unmount. Back/Cancel must never promise rollback of already committed work.

Port `AutoDismiss` as an info-flash timer (existing default 5 seconds and fade); errors remain until dismissed. Dispose timers/listeners. Port `KeystrokeCapture` as DOM capture of `code` and modifier flags with focus/preventDefault/stopPropagation; Rust normalizes the existing chord vocabulary and validates supported keys. Capture ignores modifier-only presses; explicitly test Ctrl/Shift/Alt, letters/digits/numpad/function/special keys and the existing Meta behavior before changing it.

Preserve `phx:theme` localStorage preference with system/light/dark behavior; theme is presentation state. Keep theme tokens, widths, padding, responsive cards, icons, alerts and progress visuals. Retarget Tailwind source scanning to `.svelte`/TS files and replace LiveView loading variants with component pending attributes. Remove Phoenix socket/CSRF/topbar dependencies only after equivalent loading feedback exists. Check icon asset licensing/build paths without relying on Mix-installed dependencies. No untrusted HTML rendering for script text, logs, endpoint data or release text.

## Platform integration findings

The platform proposal matches the required Rust ownership, direct IPC, shared mutations, snapshot recovery and release-checker behavior. The coordinator incorporated the first three findings during parallel review; finalize their concrete wire types in milestone zero rather than creating frontend-specific alternatives:

1. Its common EntityId must coexist with public hardware ConfigId. Route DTOs must not substitute one for the other.
2. Define revision scope, runtime epoch and telemetry resync explicitly; filtered/coalesced streams cannot use naive global `last + 1` gap checks.
3. Separate subscription disposal from session cancellation and application close. Keep firmware and MCP operations discoverable via snapshots and identify completion by session/request.
4. Preserve the precise settings write-before-test and blank-key semantics; file-only key status is current UI behavior, not proof no manual key exists.
5. “Validation” is not universally read-only in legacy UI: configuration name change currently saves. Command names must expose that distinction; all domain checks still run in Rust.
