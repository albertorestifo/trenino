## Existing architecture and approaches

`Serial.Connection` exclusively owns Circuits.UART; decoded packets arrive as `{:serial_message, port, struct}` on `serial:messages:<port>`. Its device updates include *all* tracked statuses, not just connected devices. Identity carries version and persisted legacy `config_id`; there is no board serial identity. `Hardware.ConfigurationManager` applies legacy Configure parts and emits configuration events after acknowledgement. Firmware resets axes during legacy configuration application. Therefore simply subscribing a new gauge controller to configuration-complete events would permit motion races.

`Train.DisplayController` is a useful subscription/UI pattern, but its cached display replay cannot be copied for motors. `Train` emits `{:train_changed, train_or_nil}`; simulator connection emits `{:simulator_status_changed, %ConnectionState{}}`; subscriptions are polled through `Client.get_subscription/2`. Current subscription ranges are 1000–1999 outputs, 2000–2999 scripts, 3000–3999 displays. Train and hardware editors use dedicated form/wizard components and API explorer forwarding. MCP exposes hardware and binding CRUD already.

Considered: (1) put motor writes directly in a display-style controller—small but cannot safely arbitrate commissioning/reconnect/deployment; (2) build a general actuator framework—unnecessary scope; (3) dedicated per-port stepper sessions plus pure gauge mapper and train controller—selected. Retain existing context and serial APIs where practical, adding one synchronous deployment barrier. No second UART owner and no new dependency are necessary.

## Fixed constraints

- Firmware floor: stable version >=3.1.0; extension revision 1; inspect status capability bits before Configure.
- Two logical axes (0 and 1), one shared shield address 0x60–0x77, distinct ports 1 and 2. Driver `:adafruit_motor_shield`; modes `:x27_six_state`, `:full_step`, `:half_step`. No assumed generic motor compatibility, sensors or microstepping.
- All positions, speed and acceleration are commutation transitions in the selected mode. Positions -1000000..1000000, minimum < maximum; speed 1..200 transitions/s; acceleration 1..10000 transitions/s²; watchdog 100..60000 ms.
- Home strategy `:host_reference` or `:internal_stop`; direction -1/+1, sweep 1..65535, backoff 0..sweep-1, home speed 1..max_speed, home timeout 1..60000 ms, home position within limits. For internal stop reject host configuration unless timeout exceeds `ceil(1000*(sweep+backoff)/home_speed)+500` ms. This margin is host policy, not firmware timing guarantee.
- Continuous bindings require idle `:hold`. Idle release loses reference even after Home. Host-loss behavior is separately `:release` or `:hold`, default release; both lose trustworthy reference.
- Startup referencing is configurable: `:manual` (default) or `:home_on_connect` (explicit opt-in for commissioned internal-stop axes with idle hold). Auto-Home is permitted once after a fresh connection completes acknowledged Reset/Configure and capability checks. Never automatically Reference. Never Home merely because of train activation, profile save, legacy deployment, process restart, unexpected reboot/fault recovery, or uncertain acknowledgement. No physical commands are sent merely by saving a profile.
- Position/status are open-loop estimates. Home completion must read “Assumed internal-stop reference”; never “stop detected”, “sensor homed” or physically verified.
- User-entered calibration values follow the repository's two-decimal domain convention. Preserve intermediate conversion and interpolation precision; round only the final integer target and user-facing display text. Display formatting must not alter motion targets.
- Tests must never discover, upload to, or operate real hardware. Use existing DataCase/SerialSafetyCase forbidden UART stubs.

## Wire contract and axis-only configurations

Add `StepperCommand` (type16) and `StepperStatus` (type17, exactly23 bytes), atom-based public enums, exact little-endian layouts from firmware. Configure is exactly41 bytes; target/reference10; other commands6. Validate lengths, ranges, revision and enums before encoding/decoding; no binary integer truncation or user-input atom creation. Status flags expose configured, known, energized and reference kind independently; unknown position is represented as unavailable in the UI, never zero.

Query capabilities with GetStatus on **axis0**, not axis255 (255 is accepted only by KeepAlive, Reset and ForgetDriver). Validate all advertised relevant bits. Future additional capability bits can be preserved/ignored; unsupported enum/revision must produce explicit protocol errors.

Firmware v3.1.0 is adding canonical empty legacy Configure: `[2, config_id:u32LE, 0, 0, 255]`, exactly8 bytes. It clears modules and persists the ordinary config_id without inventing an input. Host `Configure` uses `input_type: :empty`; permit only total_parts=0 and part_number=0. Gate empty deployments on >=3.1.0. Confirm final firmware implementation before fixture creation. Axis-only Apply must use this message, receive ConfigurationStored, and then configure axes. Do not invent port-based persistent identity or falsely update connection.config_id without EEPROM acknowledgement.

Axis delete releases/removes its live configuration via session reconciliation before deleting; if release cannot be confirmed, report failure and retain row. Offline delete is allowed and cascades bindings. Whole device deletion retains existing connected-device protection.

## Runtime lifecycle and arbitration

`Hardware.StepperManager` tracks connected generations and starts one `StepperSession` per port under `StepperSupervisor`. A generation includes UART pid and connection identity, not just port name; repeated unrelated devices_updated notifications must not reset a healthy session. Duplicate connected config_ids are ambiguous: refuse automatic attachment and show conflict. Manager boot reconciles already-connected devices. Sessions never open UART directly.

Session states: unsupported, probing, resetting, configuring, awaiting_reference, ready, deploying, fault, disconnected. Upon eligible identity and known device config: subscribe before querying status; capability check; acknowledged Reset; sequential Configure all persisted axes; await explicit reference unless this is a newly connected generation with the commissioned home_on_connect policy. In that case issue Home once, mark the attempt consumed before sending, and wait for confirmed completion; any failure/uncertainty latches Needs reference, never retries with a fresh request ID. Startup Home attempts run independently for two axes but shared I2C faults stop both. Merely starting/restarting a session for an already-connected board does not authorize auto-Home; Manager must distinguish a real new connection from startup reconstruction. KeepAlive begins as soon as first Configure is accepted, every `max(20, floor(min_watchdog/4))` ms. It runs during Home, waiting for users, and HTTP outages, independently of simulator polling. Use timer generation tokens and cancel on teardown. Poll axis status every250 ms while moving/homing, every1000 ms otherwise; async status can also advance state. Don't require position equality on immediate command ACK.

Use monotonically increasing nonzero16-bit request IDs shared across the session. Before wrap, block new work and perform acknowledged Reset/reconfigure, leaving awaiting_reference. One outstanding mutating operation per axis; never queue stale MoveTo requests: keep at most latest desired target. Ack timeout250ms, at most two same-byte/same-ID retries while it remains the latest axis mutation. KeepAlive/GetStatus do not overwrite axis retry history. Acceptance is not completion. Home ACK retry must use the original identical ID; on final uncertainty poll status then suspend that axis with “Home outcome unknown”; do not allocate another Home request or infer reference from elapsed time. Any reset/reconnect cancels retry history. Never retry a superseded operation. Stop/Release may preempt Home/Move: cancel pending retries and buffered targets, issue new ID; never replay earlier Home afterwards.

Correlate status by generation, axis, operation and request id; request0 GetStatus is asynchronous status, not an ACK. Late ordinary ACKs must not complete unrelated requests. Within one open UART generation, Reset/reconfigure also starts a new reference epoch: discard prior command/poll results and never promote known/ready from an unsolicited old status without an explicitly accepted Home/Reference in the current epoch. Follow that acceptance with a correlated status poll to establish completion; async updates are hints, not permission to regain a lost reference. On serial loss/upload/nonconnected status, immediately clear all references, queued targets, ownership and timers. On unexpected unconfigured/fault status (including firmware reboot with same open UART), invalidate readiness and require explicit recovery Reset/Configure then explicit reference. Session crash recovery follows initial handshake, never resumes previous targets/Home.

All runtime commands go through Manager/Session, with ownership token: `:train` controller or manual commissioning caller. Manual lease monitors caller pid, pauses automatic dispatch for that axis, clears pending desired target and Stops if necessary; it does not automatically resume after release. Session records whether a stationary reference survived Stop. On browser close/process death Stop, clear manual lease, leave automatic output paused until explicit Resume; release if configured inactive policy requests it. Manual operations may not bypass readiness/soft limits. Jog means relative MoveTo from fresh known stationary status, not guessed/unknown position. Home is the supported bounded movement for an unreferenced internal-stop motor; host-reference mode requires the user physically aligns the pointer and explicitly assigns a position.

ConfigurationManager must synchronously call `begin_deployment(port)` before sending the first legacy Configure. Session clears automatic/manual ownership and pending mutations, invalidates reference, performs acknowledged Reset, then returns a deployment token. No motion/configure can be admitted until `finish_deployment(port, token, result)`; on success re-probe/reset/configure persisted axes and await reference; on failure remain suspended/fault. If no session/axes existed, Manager still records the port barrier so a devices_updated event cannot start one mid-deployment. Ensure finish executes on send failure, device rejection, timeout, confirmation failure and disconnect. Match ConfigurationStored/Error by *both port and config_id*, reject concurrent deployment on the same port, and ignore stale completion tokens. Never have Session synchronously call ConfigurationManager while ConfigurationManager waits on Session. Keep querying DB outside cyclic synchronous paths.

Address changes are explicit “Recommission shield address” workflow: pause both axes, Reset, ForgetDriver, then Configure with the new address, awaiting reference. An ordinary failed Configure/resource-conflict must not automatically ForgetDriver. This operation applies to the whole shield/device; persisted axes must use the same new address. Show ALLCALL commissioning instructions before first registration or address change: disconnect 0x70 display, register shield alone, then reconnect/apply display config. Software cannot safely discover an unregistered PCA9685 by probing writes. Require explicit commissioning action/acknowledgement, not a checkbox auto-filled by a template.

## Train controller and failure policies

`Train.GaugeController` uses 4000–4999 subscriptions, deduplicates by endpoint, polls200ms, bounds range to1000 unique endpoints. Resolve a selected value_key; when omitted accept only a single numeric value, never `Map.values |> List.first` from an ambiguous response. Require NodeValid=true, reject empty/multiple Entries unless the selected endpoint resolves unambiguously. A timeout/non-numeric/invalid node keeps last accepted target only until stale_after_ms then applies inactive behavior once and shows stale; no default zero target. Use timestamp of successful sample receipt.

HTTP work must be asynchronous/bounded, one poll generation in flight, so slow simulator requests cannot prevent device lifecycle messages or train switch. Drop results tagged with old train/subscription generation. Clean subscriptions using the old client on deactivate/change/disconnect; retry failed subscription setup with bounded backoff while still active. On connected simulator recovery reacquire subscriptions and fresh values; never reuse stale previous-train samples.

Train activation/reload creates subscriptions but can only request targets on commissioned, ready, referenced axes with train ownership and explicit Resume after manual pause. If no manual pause and axis already referenced, newly activated train may control it. After hardware reconnect show Needs reference unless an opted-in startup Home is in progress; successful startup Home permits normal train ownership, using only a fresh sample. For manual policy, a Home/Reference action plus Resume makes the latest *fresh* sample eligible. Inactive hold sends Stop, not a remembered MoveTo; if moving this loses reference, as firmware specifies. Inactive release sends Release and loses reference. Simulator disconnect/stale/deactivation/train change use the outgoing binding's inactive policy. No parking move is necessary in this scope. Preserve reference only if firmware confirms it remained known while stationary.

## User interface and useful Class 323 setup

Advanced settings may be folded but editable. Saving is distinct from Apply. Axis card shows connection, configuration, status, estimated position/target, known/reference kind, energized, faults, commissioning state and train/manual ownership.

Disable actions in UI *and server-side* when unsupported/busy/disconnected; handle forged/stale ids without exceptions. Recovery never silently moves. ## MCP, documentation and completion

Add axis CRUD/status/explicit runtime control and gauge CRUD/preview tools, using same contexts/session validation as UI. Runtime tool requires explicit operation and manual lease, cannot implicitly move on CRUD. MCP manual leases are opaque tokens stored by Manager with60-second expiry, renewed only by an explicit renew operation, not owned by ephemeral HTTP request processes. Expiry Stops and leaves automatic control paused. Every mutating tool call supplies an operation_token; repeating the same token with identical operation/arguments returns its pending/completed admission result without a new firmware mutation; changed arguments reject. Retain token results for the lease lifetime, bounded to100 operations per lease, then require a new lease; reject rather than silently evict an old token. Disconnect/reset/reconfigure revokes leases. Include safety/status semantics in tool descriptions, return actual ACK/pending/fault state, and never report physical completion merely because a command was sent. Register modules and update all three hardcoded registry count tests per CLAUDE.md.

Document commissioning, wiring assumptions, ALLCALL registration order, capability floor, units, mapping, stale behavior, reference loss, retries, release/hold, recovery, two-axis shared faults and Class323 setup. Automated completion requires migration, protocol golden fixtures, runtime races/fault tests, mapper/domain tests, LiveView end-to-end flow tests, MCP parity, and `mix precommit`. Actual motor travel/homing/pointer fit is explicitly unverified until a human performs the checklist; this is not a reason to leave the software incomplete.
