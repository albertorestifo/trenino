## What the final merge actually changes

1. **Standard Tauri stable updates, not Microsoft Store/MSIX.** `tauri/src-tauri/Cargo.toml`, `src/lib.rs`, new `src/updater.rs` / `src/update_flow.rs`, `tauri.conf.json`, and `tauri.updater.conf.json` add optional `desktop-updater`, native Help → Check for Updates, the committed public verification key, stable GitHub `latest.json`, and passive Windows installation. No automatic background check/restart is introduced. Nightly/development remains outside this feature.
2. **Ordering and lifecycle.** User confirmation precedes download; the official plugin download completes before shutdown, then install. Cancel/download/signature/shutdown failures do not invoke installation. The legacy adapter POSTs `/api/shutdown`, then waits up to 15 seconds for the owned backend's `Terminated` event (`BackendExited`), without force-killing it in the updater path. Install failure after successful shutdown requires reopening the app. The ordinary existing exit handler still has its old force-kill fallback; do not confuse that with updater behavior.
3. **Distribution-aware notifications.** `src/lib.rs` passes `TRENINO_DISTRIBUTION=tauri-updater` for enabled builds; `config/runtime.exs` disables only `start_app_version_checker`. Firmware update notifications remain enabled. Direct/server builds retain their application release notifications.
4. **Release signatures.** `.github/workflows/release.yml` enables the feature and updater overlay, uploads updater JSON/signatures, prefers NSIS for Windows metadata, and skips the verify-version job for prerelease events. These updater signatures are distinct from Windows publisher Authenticode. Preserve existing public-key continuity and do not run signing setup or rotate anything during rewrite work.
5. **Signing regression checks.** `scripts/setup-updater-signing.ps1` verifies both public-file agreement and a real fixture signature against the embedded public key before uploading either secret. `scripts/test-updater-signing.ps1` uses throwaway keys and an intercepted upload boundary to reject stale-public/different-private pairs, accept a valid signature, and reject tampering. The helper package is `scripts/updater-signature-verifier/`.
6. **Installed vJoy resources.** `scripts/build-desktop.sh`, `scripts/stage-vjoy-resources.ps1`, and `tauri.windows.conf.json` now stage/package `vJoyInstall.dll` beside `vJoyConfig.exe`; it is a loader dependency even for query-only operations. `SystemAdapter.trusted_locations/0` in `lib/trenino/virtual_joystick/configurator/system_adapter.ex` adds the absolute launcher `APP_PATH/resources` ahead of existing extracted-backend locations, retaining existing trust validation. No PATH/CWD search is introduced.
7. **Installer and CI.** Installer warning text distinguishes an unsupported version/state from an unsigned driver and preserves unowned shared drivers. CI extracts NSIS, checks the added DLL and runs the packaged configurator's read-only query. The Burrito setup action stages a hash-pinned Windows Tailwind binary. These legacy build prerequisites remain until actual release cutover.
8. **Firmware tests only.** `test/trenino/firmware{,/downloader,/firmware_file}_test.exs` changes isolate per-test cache names and remove only each test's file instead of globally deleting `.hex` files. No firmware schema or migration change is present.
