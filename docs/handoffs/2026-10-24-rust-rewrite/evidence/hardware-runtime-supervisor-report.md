# Hardware runtime supervisor review

Review target: `6c2d99b..8723455`, branch `codex/rust-rewrite`.

**Final verdict: specification not accepted; quality changes required before adapter integration or hardware acceptance.** Own audit and both fresh independent reviews are complete. The aggregate contains eight P1 findings and three P2 findings below. No P0 is asserted by the supervisor.

## Scope and evidence

Reviewed the hardware runtime, discovery, native transport, configuration, sessions, routing, shared arbiter, protocol frame bound, and focused tests against the hardware runtime brief. Scoped production sources were verified unchanged from `8723455`. Shared `fs2` is a coordinated AppServices prerequisite; sibling firmware/AppServices/Tauri changes are excluded.

No production code edits or commits. No physical ports, drivers, simulator, firmware flashing, or user database access. The supervisor's standalone fake probes are retained as `hardware-runtime-supervisor-probes.rs` in this directory. They include the exact scoped production modules and link already-built core/serialport libraries. Five probes passed in 0.11 seconds, where **passing asserts reproduction of a defect**, not correct product behavior. Each blocked fake is explicitly unblocked and its drop awaited.

## Aggregate findings

1. **P1 — Cleanup loses ownership and shutdown reports success while a port is live.** `hardware/mod.rs:239-255`, `339-346`, `578-593`. `OwnedPortTask::close` consumes the task, takes its JoinHandle and drops that handle on timeout; the blocking serial thread and handle remain live. The scanner reports a Failed event but returns `()`, so `DiscoveryHandle::shutdown()` returns `Ok(())`. Failed handoff/removal also removes the task without retaining a quarantine reservation, allowing a later scan to open the same port again. Probe `probe_shutdown_reports_success_while_port_still_open` observes Ok, zero native-owner drops, and a cleanup error event before unblocking the fake. Required: retain ownership of unfinished workers, quarantine their ports, aggregate shutdown failure in the returned result, and offer an owned join/recovery path. Do not release or rediscover a port until closure is proven.

2. **P1 — A second handoff overwrites a live reservation.** `hardware/mod.rs:431-456`. Handoff checks only `ports`; after the first handoff the port is absent, so the second request writes generation zero over `reserved_ports`. The first token becomes invalid and releasing the second permits rediscovery while the first holder is still active. Probe `probe_second_handoff_overwrites_first_reservation` reproduces the invalid first token and rediscovery. Required: return Busy for an already reserved/quarantined port and issue unique opaque reservation tokens, including initially disconnected ports. Timed-out handoff callers also need a recoverable operation result rather than losing the only token.

3. **P1 — Discovery drops authoritative inputs coalesced with identity.** `hardware/discovery.rs:86-99`, `hardware/mod.rs:114-120`. Returning the identity from inside `decoder.push(...)` discards every later decoded frame in the read and any incomplete frame retained by that discovery decoder. The worker creates a new decoder. Probe `probe_discovery_silently_loses_coalesced_input` supplies identity plus a button edge in one read and receives only Discovered. Required: transfer decoder state and all trailing decoded messages to the persistent owner; preserve their order and test complete and partial trailing input frames.

4. **P1 — Runtime treats recoverable malformed frames as connection failure.** `hardware/mod.rs:153-174`. The bounded decoder can resynchronize after a delimiter, but the worker sets `failed` and breaks the batch on the first decode error, dropping valid following packets. The scanner then removes the port and waits for retry. An overlong frame followed by delimiter and valid button edge in one read therefore does not satisfy the specified recovery contract. Required: report protocol error/overflow visibly while continuing decoder resynchronization and processing subsequent valid frames; reserve connection failure for I/O/lifecycle failure.

5. **P1 — Writes cannot be fenced to the caller's connection generation.** `hardware/mod.rs:268-274`, `296-318`, `415-429`. Runtime writes carry only a port name and message; scanner dispatch resolves whichever worker currently occupies that port. A producer retaining generation N can send configuration/output data after reconnect and affect N+1. Required: make expected generation part of every write command and validate at dispatch and the worker boundary; bind configuration acknowledgements to the same owned operation. Add a deterministic reconnect-plus-stale-write fake test.

6. **P1 — Resolver invalidation does not revoke a generation.** `routing.rs:29-77`. Invalidation removes the route map without recording a tombstone or advancing the generation watermark. `replace_port` accepts equal generations, so a late callback can resurrect a disconnected map. Probe `probe_invalidated_resolver_can_be_resurrected` shows invalidate(5), replace(5), resolve(5) succeeds. An invalidation for a new generation without a current map also leaves the older watermark intact. Required: atomic generation/lifecycle state with separate reconfiguration and terminal disconnect semantics; stale replace must not reactivate a disconnected generation. Cache activation needs the same revocation/operation-token distinction.

7. **P1 — Detection is not an owned timed, generation-fenced operation.** `hardware/sessions.rs:35-100`, `281-394`. Registry retention preserves allocation after UI drop, but no owner drives timeout, dispatch, completion publication, or removal. Timeout is checked only by `observe`; a quiet/disconnected board never produces a timeout result. Detection has no generation argument; registry `source_lost` updates only calibrations. Probe `probe_detection_uses_baseline_after_registry_source_loss` shows detection using its pre-loss baseline after registry source loss. Successful detection also has no terminal latch. Required: service-owned session task/dispatcher with injectable clock, autonomous timeout, terminal result retention/publication, generation-aware baselines/source loss and bounded registry cleanup. This is a runtime ownership requirement, separate from the explicitly deferred desktop/database adapters.

8. **P2 — Discovery has no enforced 10-second outer deadline.** `hardware/discovery.rs:45-67`, `hardware/mod.rs:21`. `DISCOVERY_TIMEOUT` is never used. Pre-request garbage draining loops until a quiet read with no elapsed-time bound; a noisy board can prevent the first identity attempt indefinitely. Reads near attempt boundaries can also overrun the per-attempt budget. Required: deadline spanning settle, drain, requests, reads and writes, with remaining-time-aware transport operations and explicit cleanup on expiry. Add fake-clock continuous-noise and blocked-I/O cases.

9. **P2 — Calibration result/error and memory bounds are incomplete.** `hardware/sessions.rs:205-216`, `237-274`. Draining `sample_events` makes room while the three retained sample vectors grow without a total bound. `advance_and_persist` sets Complete before persistence and stores neither the resulting calibration nor the persistence error; a later observer cannot recover the result if the original listener disappears. Required: bound retained authoritative samples separately from notification delivery, preserve ordered samples, and retain the terminal success/error for the owned operation. Preserve the legacy public result rather than representing every save outcome only as Complete.

10. **P1 — The internal runtime dispatcher/operation ownership is missing.** `hardware/mod.rs:387-599`, `hardware/configuration.rs:7-11`, `hardware/sessions.rs:279-399`. The scanner owns serial tasks and emits a raw callback, but owns none of the shared resolver, cache, sessions or arbiter. No production event path performs lookup/routing, queues authoritative inputs, dispatches configuration ACKs, applies source-loss to sessions or ties calibration to an arbiter lease. There is no production `ConfigurationPort` implementation. Public `handoff_port` also accepts no verifiable same-port/same-generation firmware lease; it can be called without consumer suspension, calibration cancellation or neutralization. The required internal orchestration cannot be deferred under the database adapter/desktop wiring exclusions. Required: a runtime-owned state/dispatcher and owned operations with injected repository/consumer adapters; prove discovery-to-routed-input, ACK persistence, disconnect invalidation, calibration cancellation and firmware handoff end to end with fakes. Enforce handoff ordering through that operation owner or an arbiter-issued capability. Public helper types and documented caller obligations alone do not satisfy the delivered ownership contract.

11. **P2 — Serial command queues have no capacity or backpressure.** `hardware/mod.rs:80`, `230-236`, `302-316`, `392-393`. Both command channels are unbounded. Holding fake I/O while issuing concurrent writes retains each message and reply sender; caller timeout marks cancellation but does not remove pending allocations. Required: bounded queues with explicit Busy/Overflow, cancellation-aware dispatch, and deterministic failure/draining during shutdown. Verify queue capacity while one fake write is blocked and preserve ordered authoritative data independently from preview delivery.

## Independent correctness review adjudication

Its cleanup severity is normalized from P0 to P1 here: the defect is release-blocking, but the evidence does not establish universal catastrophic impact. ## Independent adversarial review adjudication

The second fresh `gpt-6-sol` / high reviewer independently returned **spec not accepted / quality changes required** in `hardware-runtime-adversarial-review.md`. It confirms cleanup, generation-unbound writes/handoff, resolver resurrection, session lifecycle and discovery deadline defects. Its P0 cleanup severity is normalized to P1 on the same basis. Its direct handoff bypass finding is incorporated into finding 10; its unbounded command queue finding is retained as finding 11.

It also establishes the timeout limb of finding 2: choose a handoff caller timeout shorter than fake close completion, and close completion shorter than the scanner cleanup deadline. The caller drops its reply receiver, but the scanner subsequently commits the reservation and loses the token when reply delivery fails. This requires a retrievable owned operation result or an explicit safe abort. A release timeout must likewise expose whether release committed. These are source-level reproductions, not claimed executable probe results.

Both child reports are preserved independently and unchanged. They performed static reviews with concrete fake call-sequence reproductions. The supervisor alone ran the five executable fake probes listed above. Root independently reports a passing integrated suite (152 tests) and strict workspace Clippy; those checks do not exercise or negate these counterexamples.

## Fix and acceptance sequence

First retain failed/closing owners, quarantine their ports and propagate shutdown failure; make reservation tokens opaque, non-overwritable and recoverable across caller timeout. Next introduce the owned dispatcher/operations and expected-generation commands, with coordinated resolver/cache epochs and arbiter-authorized handoff. Preserve decoder state across discovery and recover malformed streams at the worker boundary. Complete autonomous session deadlines, retained terminal results and queue/sample bounds. Add bounded fake regression coverage for each finding, then repeat the focused existing suites. Actual repository/desktop wiring and explicit physical-board acceptance remain later gates.

## Positive checks and integration boundaries

The custom COBS bound calculation covers the 520-byte matrix layout with a 523-byte encoded limit, and the core decoder has explicit discard-through-delimiter recovery. ConfigId rejects zero. The transport retains cross-platform source use with pinned serialport and no default libudev feature. The shared arbiter explicitly chooses global lease exclusivity while consumer suspension is port-scoped, and its tested handoff path avoids fresh-sample resumption between calibration and firmware. Configuration confirms through the repository before success publication in the non-racing path.

Database adapter, AppServices/desktop wiring, real consumer adapters and physical-board acceptance remain legitimate explicit gates. Those gates do not cover the scoped defects above or substitute for required runtime task ownership.
