## Supervisor-confirmed findings

1. **P1 — SQLite sidecar backup paths can destroy the promised backup.** `src/storage/migration.rs:135-143,186-197` excludes only the source filename and already-existing paths. On a current fixture in DELETE journal mode, passing `source.db-journal` as backup returns `Ok(MigrationReport { source: Current, ... })`, changes source user_version to 2, and leaves `backup_exists=false`. SQLite overwrites/removes that file as its rollback journal during the migration. Reject the source's reserved `-journal`, `-wal`, and `-shm` paths before creating anything; normalize relative and canonical directory aliases and platform filename equivalence. Regression: fixture in DELETE mode with nonexistent source-journal backup, plus WAL/SHM aliases, must be refused without source mutation or target creation. A normal backup must remain independently reopenable with the complete pre-upgrade state. Probe: `storage-supervisor-probe/main.rs`.

2. **P1 — Schema/version admission is outside the writer reservation.** `migration.rs:145-158` completes admission before BEGIN IMMEDIATE. Supervisor held a competing IMMEDIATE transaction, started migration, inserted Ecto version 20990101000000 while migration waited for its write lock, and committed. Rust migration returned success, source user_version became 2, and Ecto max(version) remained 20990101000000. `validate_full_schema` does not recheck the Ecto inventory. Recognition and data checks must run/re-run inside the acquired transaction, before backup, and the target should enforce its expected retained Ecto baseline. Regression: deterministic concurrent-writer barrier changes the inventory/header/schema before reservation acquisition; assert refusal, preservation of the competing writer's state, no Rust changes, and no backup creation. Also cover an ordinary data writer to prove snapshot and transformation see the same admitted committed state. Caller quiescence is still a lifecycle requirement but does not satisfy unknown/newer refusal. Probe: `storage-supervisor-probe/race.rs`.

3. **P2 — A normal relative backup filename fails path validation.** `migration.rs:188-189` treats a missing parent as '.', but `Path::parent()` returns an empty parent for `backup.db`. `migrate_legacy(absolute_fixture, "backup.db")` from the fixture directory returns Backup with Windows OS error 3. Source remains legacy and no backup exists. Treat empty parents as '.', then use the same normalized path for alias protection. Regression: both absolute and bare relative backup paths succeed; relative same-source and sidecar paths remain refused. Probe: `storage-supervisor-probe/relative.rs`.

4. **P2 — Historical fixture toolchain provenance is not yet demonstrated.** The scripts do execute the real tagged 36 migration modules and current 41 modules. However, both run against the arbitrary supplied EctoCheckout/BuildPath, rather than the tagged lock/build. v0.7.4 pins Ecto 3.13.5, ecto_sqlite3 0.22.0, exqlite 0.33.1; current pins 3.14.0, 0.24.1, 0.37.0. Since admission compares exact sqlite_master SQL, tagged source provenance alone cannot prove real release database compatibility. Regenerate the historical baseline with the tagged locked dependencies, or establish documented byte-for-byte schema equivalence using that runtime, and preserve that evidence in the fixture generation flow. Both old/current ecto_sqlite3 and exqlite package archives are already cached under C:/Users/Alberto/.hex/packages/hexpm. Supervisor compared the adapter connection sources; the changed sections do not themselves prove a relevant DDL difference, so this is an acceptance-evidence gap, not a claim that historical databases are known to fail. Do not relax fingerprint checks blindly.

5. **P2 — Current-schema trains with no identifiers are migrated unchanged.** Independent correctness review identified `migration.rs:252-272,342-349`: schema/FK admission accepts a current train after deleting its last `train_identifiers` row, because the foreign key constrains child ownership but cannot require a child to exist. The legacy train changeset (`lib/trenino/train/train.ex:54-79`) requires at least one, and the platform plan names this acceptance case. Reject such data before migration writes rather than inventing an identifier. Regression: current disposable fixture with zero identifiers for an existing train must be refused with unchanged source; later train repositories must prevent removal of the final identifier. This finding is source-derived, not an additional executed supervisor probe.
