## Remaining issues for round 2

1. **P1 — Shutdown hangs when its command cannot enter the subscription queue.** In `crates/trenino-runtime/src/simulator/subscriptions.rs:229-235`, the `shutdown` branch beginning with `if let Err(error) = send_result` awaits the worker for every send error, including QueueTimeout. When the bounded queue is full, the Shutdown command was never enqueued. After previous work drains, the actor waits for another command while shutdown retains its sender and awaits that actor forever. This is introduced by the new actor shutdown implementation and prevents acceptance of original finding 1.

   Actual compiled-runtime reproduction used only a disposable local HTTP server: Fast profile (500ms admission budget), one gated subscription request, 64 queued Counts calls, and a first shutdown call. After 650ms the server gate was released; the acquisition and all 64 Counts calls completed, leaving the actor idle. The first shutdown was still unfinished after another 100ms. Calling shutdown a second time rescued both calls, each returning Ok. This establishes the missing-command deadlock rather than merely a slow HTTP request. Do not await termination following QueueTimeout unless termination was independently requested; return an explicit retryable admission error or use a guaranteed shutdown control path. Only join a worker known to be terminating/terminated. Add the saturated-inbox regression, including the absence of a second shutdown call; retain retryable cleanup diagnostics.

2. **P2 — Raw float formatting still differs at exponent-selection boundaries.** `crates/trenino-core/src/simulator.rs:76-92` (`SimValue::to_legacy_string`) starts from Rust Debug rendering and repairs a missing decimal marker only when that rendering already uses an exponent. The actual installed Elixir returns `Float.to_string(1000000000000000.0) == "1.0e15"`, while the actual compiled Rust helper returns `"1000000000000000.0"`. Existing 1e20/1e-8 fixtures therefore close the original examples but not finding 8's float text contract. Implement the legacy notation choice, not just mantissa repair, and add cases immediately around its fixed/scientific boundaries. The same helper now feeds get_string and analyzer descriptions, so fix it centrally.

3. **P2 — Newly added integer output branches discard the precision just preserved by the DTO.** Every new `SimValue::Integer` arm in `crates/trenino-core/src/train/output.rs:29-58` casts i128 to f64 before comparing it with the configured floating threshold. The compiled-core probe with integer 9007199254740993 and threshold 9007199254740992.0 returns Gt=false and Lte=true. The installed Elixir returns true and false respectively. The integer is legal JSON within u64 range and the new deserializer now preserves it exactly; these casts lose that exactness again. This is a related incomplete integration of finding 8's new integer representation, in code changed by this fix. Compare integer and floating operands without first rounding the integer to f64; cover positive/negative precision boundaries, the inclusive between operator and ordinary mixed values. No change to boolean-only operators is needed.
