## Numbered findings and fix requirements

1. **P1 — Subscription ownership and cleanup are not cancellation safe.** `crates/trenino-runtime/src/simulator/subscriptions.rs:155-166` registers a lease before awaiting subscription HTTP. Cancellation drops the future without returning its lease or rolling back ownership. Supervisor and adversarial reviewer independently aborted acquisition after a fake local server observed the POST: lease_count stayed 1. Supervisor then acquired the same endpoint for another owner: it reused ID 1000 without another POST; releasing that owner returned no cleanup IDs and left the unreachable first lease. At `subscriptions.rs:189`, draining pending cleanup IDs across an awaited unsubscribe can permanently discard IDs on cancellation. Additionally, ordinary failed unsubscribe consumes the lease first (`subscriptions.rs:173-176`); retained failed IDs are retried only on a later release or failed acquisition, so idle failure has no recovery path and retrying the lease returns UnknownLease. Move operation/cleanup ownership to a service task or another cancellation-safe mechanism, preserve each pending ID until successful cleanup, and provide explicit retry/drain/shutdown behavior. Add deterministic tests for cancellation during creation, cancellation during multi-ID cleanup, creation failure after partial success, and failed cleanup followed by no other consumer traffic. This is a defect in the shipped service, independent of future UI/controllers.

2. **P2 — Source rounding parity is wrong.** Multiply-then-round helpers at `crates/trenino-core/src/train/lever.rs:103`, `crates/trenino-core/src/calibration/analysis.rs:173-177`, `crates/trenino-runtime/src/simulator/client.rs:283`, and `crates/trenino-core/src/train/display.rs:78-81` introduce another binary rounding step. The correctness reviewer ran Elixir/Rust probes: Float.round(0.015, 2) is 0.01, while the Rust helper yields 0.02, changing a full-range linear lever's output. Float.round(0.15, 1) is 0.1, while Rust yields 0.2; an analyzer zone spanning outputs 0.0..0.15 therefore changes from gate to linear. Supervisor independently ran the installed Elixir oracle and the actual compiled Rust library for 2.675: legacy numeric/display rounding gives 2.67, Rust gives 2.68. Port the actual source rounding semantics, including display formatting, with golden cases around positive/negative ties and analyzer classification thresholds. Do not replace them with an assumed equivalent formatting expression. The correctness reviewer rated this P1; supervisor rates it P2 for the currently unconnected slice, but it blocks parity acceptance.

3. **P2 — Latching sequence release omits cancellation.** `crates/trenino-core/src/train/buttons.rs:155-169` emits CancelActive only for momentary hardware. Active latching release emits StartSequence without cancelling the old on sequence; with an empty off sequence it emits no cancellation and leaves active true. Legacy `lib/trenino/train/button_controller.ex:492-494` cancels active work before handling every sequence release. Supervisor's compiled-library probe confirmed active latching release returns only StartSequence. Emit cancellation before any off-sequence start, and clear active state when no replacement starts. Correct `crates/trenino-core/tests/controls_parity.rs:329-346`, which currently encodes the divergence; test active release both with and without an off sequence. The correctness reviewer rated this P1; supervisor rates it P2 because only the pure action planner is delivered. The eventual controller must prove that the cancellation effect is actually awaited before starting replacement effects.

4. **P2 — Invalid-key health errors are incorrectly transient.** `crates/trenino-runtime/src/simulator/connection.rs:78-91` treats InvalidKey like Timeout. A compiled-library probe returned CheckAfter(2s), with status still Connected. Legacy `lib/trenino/simulator/connection.ex:249-260` moves directly to error on an invalid key; only transient failures use the three-failure threshold. Add the permanent-error transition and its exact health decision/state fixture. Current lifecycle tests cover only timeout failures.

5. **P2 — Non-JSON HTTP errors lose their status.** `crates/trenino-runtime/src/simulator/client.rs:252-267` requires JSON before considering status. Both reviewers identified this, and the adversarial local-server probe confirmed a plain-text 403 returns InvalidJson instead of InvalidKey. Non-JSON server errors similarly lose their HTTP status. Legacy `lib/trenino/simulator/client.ex:377-385` classifies status independently of body decoding. Classify status first and retain a usable raw error body when JSON is unavailable; require the proper envelope only for operations that need it. Cover empty/plain-text 403 and plain-text 5xx as well as the existing JSON 403 case.

6. **P2 — Queue admission timeout excludes contention for admission, delaying fencing and shutdown.** `crates/trenino-runtime/src/simulator/writer.rs:131` awaits the mutex before the timeout at lines 141-146. `advance_generation` likewise waits at line 153 before changing the generation at line 160; shutdown waits at line 177. Supervisor saturated capacity 1 behind a gated local HTTP request, set a 20ms queue budget, then launched five callers. Their QueueTimeout results arrived at approximately 21/42/64/85/106ms: each mutex waiter receives a new timeout after previous waiters finish. Thus admission is not bounded by the advertised per-call budget, and queued old writes can run while a requested generation switch waits to begin. Bound the entire admission phase against one deadline and arrange generation invalidation/shutdown admission so they cannot sit behind an arbitrary backlog. Add several-contending-callers and saturated-switch tests. The adversarial reviewer rated this P1; supervisor rates it P2 and narrows the claim: the evidence does not show an old write overtaking a successfully completed generation barrier. The existing serialized in-flight barrier works for calls that reach it.

7. **P2 — Numeric conversion can return success with infinity or silently clamp an integer.** `client.rs:143-146` checks finiteness before its overflowing round2 operation. Adversarial local HTTP probes observed JSON 1e307 -> get_float Ok(inf), and JSON 1e20 -> get_int Ok(9223372036854775807) through the float-to-i64 cast at lines 127-130. Supervisor's actual core-library probe also obtained Ok(inf) from a gate with finite f64::MAX simulator bounds. Similar arithmetic appears in analyzer gate midpoint/rounding and display formatting. Reject invalid/out-of-range conversions explicitly, use stable arithmetic or preserve already-large finite values where appropriate, and validate derived results before returning success. Keep numeric range decisions explicit rather than silently saturating a narrower Rust integer. Add large finite positive/negative response cases, overflowing midpoint/interpolation cases, and integer boundary tests. SimValue serialization already rejects non-finite values; that does not repair these earlier successful computations.

8. **P2 — The numeric DTO/formatter loses raw-display compatibility.** `crates/trenino-core/src/simulator.rs:107-114` decodes all JSON numbers through f64, and `crates/trenino-core/src/train/display.rs:69-75` uses Rust Debug formatting. Supervisor ran both the actual Rust formatter/serde path and Elixir to_string: JSON integer 12 becomes "12.0" instead of "12"; 1.0e20 becomes "1e20" instead of "1.0e20"; 1.0e-8 becomes "1e-8" instead of "1.0e-8". Ordinary float 12.0 correctly remains "12.0". Preserve integer-versus-float information needed by the legacy raw token, and implement compatible float text rendering. This exposes a limitation in the planned Number(f64) contract as well as the implementation; adjust that contract deliberately. Add serialized integer/float and exponent cases. A test constructed directly with Number(12.0) cannot prove integer-wire parity.

9. **P2 — Normal read retries omit transient HTTP statuses.** `client.rs:241-247` returns immediately for every received response and retries only send timeout/connect errors. Legacy `client.ex:65-67` selects Req's transient policy with two retries. Pinned [Req 0.7.4 source](https://raw.githubusercontent.com/wojtekmach/req/v0.7.4/lib/req/steps.ex) includes 408/429/500/502/503/504, so a normal GET receiving 503 has lost recovery behavior. Preserve the safe-read transient policy and test status-then-success, exhausted retries, and fast-profile no-retry behavior with local fixtures. Do not automatically re-enable mutation retries: the implementation report already declares their omission, and the migration plan warns about duplicate effects. That recorded mutation decision is distinct from the unrecorded read regression.

10. **P2 — Accepted endpoint dot segments can escape the operation path.** `client.rs:286-295` preserves dot/slash segments and its URL join at lines 227-230 normalizes them. Adversarial local HTTP probe: get("A/../../info") sends GET /info, escaping the intended /get/ prefix. Endpoint::new currently accepts that text, and raw string methods bypass the Endpoint type altogether. Enforce operation-path confinement consistently across list/get/set/subscribe, rejecting unsupported traversal segments or using a construction/encoding scheme that cannot reinterpret them. Test literal dot segments, encoded delimiters, question/hash characters, Unicode, and ordinary valid TSW paths. The configured origin was not escaped in this probe. The adversarial reviewer called this apparently inherited; exact legacy end-to-end normalization was not executed, so this report establishes the Rust boundary defect without claiming a proven new legacy regression.

11. **P2 — Inherited cross-origin simulator-key forwarding remains an integration risk.** `client.rs:79-90` installs DTGCommKey as a default header and retains reqwest's redirect policy. The adversarial two-local-server probe confirmed a dummy key reached the redirect destination. Reqwest's local source removes standard authorization headers, not this custom header. Pinned [Req 0.7.4 source](https://raw.githubusercontent.com/wojtekmach/req/v0.7.4/lib/req/steps.ex) similarly leaves the custom header, so this is inherited, not a migration regression. Before live integration, explicitly prohibit cross-origin redirects or confine credential forwarding to the configured origin, and test it. Record the behavior as an intentional safety correction. The adversarial reviewer rated it P1; supervisor rates it P2 for the present local-simulator boundary and keeps its inherited status explicit. Only dummy credentials and disposable local servers were used.

## Scope and adjudication

The writer truly limits HTTP concurrency to one per writer and owns its worker. Dropping an individual write waiter intentionally leaves that worker request running; the observed in-flight generation barrier prevents the old request from completing after a successfully acknowledged barrier. No stale-effect-after-successful-neutralization claim is made. There is no integrated button/sequence/keyboard owner to judge for held release recovery, no runtime lever coalescer/cache to judge for success-only acknowledgments, and no live output/display controller whose failed-send cache can be assessed. Treat these as remaining migration gates, not disconnected models that already prove integration.

Legacy simple-button caching advances even when its send fails, and legacy HTTP 200 envelopes are accepted without checking a Result string. Those were not silently reclassified as new Rust bugs. Full aggregate validation/CRUD, identifier train-name extraction/detection, endpoint discovery, calibration collection/wizard checkpoints, routing revision barriers, task supervision/reconnect, OS key ownership, hardware display encoding, Lua and UI workflow parity remain out of this delivered slice. The implementation report must continue to make that scope visible.
