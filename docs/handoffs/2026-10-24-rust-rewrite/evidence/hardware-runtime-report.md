## API contracts for the next adapters

- Construct `HardwareRuntime::new(Arc<impl SerialTransport>, DiscoveryTiming::default())` without scanning. Call `start(event_sink)` explicitly. `DiscoveryHandle::send_message` requires an expected generation. Firmware handoff uses an arbiter-issued permit plus `begin_handoff` and a recoverable operation ID; reservation release has a second operation ID and retained result. `shutdown(&mut self)` returns a timeout while ownership remains and can be retried. `PortEvent` carries generation on discovery, messages, diagnostics, failures and close events.
- Production defaults are 115200 baud, 3000 ms settle, five attempts with 1000 ms reads, 60000 ms scans, 30000 ms failed-port retry, and a 5000 ms task cleanup deadline. `discover_owned` enforces a 10000 ms outer budget spanning settle, stale-byte drain, requests, reads and writes. `DiscoveryTiming` and `HardwareRuntime::with_policy` allow fake tests to shorten waits.
- A configuration adapter implements `ConfigurationPort` and `ConfigurationRepository::confirm_configuration(device_id, config_id)`. `apply_configuration` takes a `ConfigurationApply` request containing the port, generation, device/config ids, messages, mappings and timeout. It invalidates old routing/cache state first, sends all supplied multipart messages, ignores stale ACK ids, checks the connection generation before confirmation, persists confirmation, then atomically replaces routes and publishes success. No database is opened here.
- The full-schema adapter can implement `CalibrationRepository::persist_calibration(input_id, Calibration)`. `HardwareSessions` owns sessions beyond UI-handle lifetime; `cancel_calibration`, `cancel_detection`, `source_lost`, and `shutdown` provide lifecycle transitions.
- All simulator/vJoy consumers must share the service's `ResourceArbiter` and implement `HardwareConsumers` (which extends `ResourceConsumers`). `suspend_actuation(port)` is scoped to the affected port. `resume_after_fresh_sample(port)` must wait for a fresh current-generation sample. Firmware startup uses `HardwareServiceHandle::acquire_firmware_lease`, `begin_firmware_handoff`, waits/polls the retained result, releases the reservation after flashing, then releases the lease. The arbiter globally serializes leases; a second active request gets `Busy`, including one for another port.

## Ownership and safety behavior

- The service does no scan/open work until `start`; the scanner owns every active task. Disconnect, failed reads/writes, handoff and shutdown revoke the active generation before stale events can be forwarded. Timed-out close retains the task and handle in quarantine; shutdown reports the incomplete close and can be retried. Shutdown with a live firmware reservation also remains pending until the matching token is released.
- A port remains reserved after handoff until the matching opaque token is released. Releasing schedules rediscovery, which produces a newer generation. Failed cleanup does not silently resume actuation or allow another open.
- Input route replacement and cache updates reject lower generations. Cache invalidation rejects more samples from the disconnected generation; an explicit activation clears cached values after persisted configuration.
- The shared lease arbiter suspends only the affected port's actuation. It allows one lease globally at a time. A firmware request on the same port asks calibration to cancel, waits for its lease release without resuming actuation, then awaits source-loss neutralization. Release waits for consumer confirmation of a fresh sample. A failed consumer transition remains fail-closed.
- Authoritative input/sample queues are bounded and return `QueueError::Overflow`; calibration records its overflow state. The port event stream preserves message order. UI preview coalescing is outside this routing path.

## Remaining integration gates

- `AppServices` does not yet construct or register this runtime. A single repository adapter still needs to look up the full configuration and persisted input mappings and implement the two repository traits. The current slice accepts validated configuration messages and mappings from its caller.
- Simulator/vJoy consumer implementations must connect actuation suspension, source-loss neutralization and fresh-sample resume to the shared arbiter. The resource contract is tested with fakes but is not wired to those consumers here.
- Firmware execution must call the explicit port-handoff API and release it after the flash process exits. The flasher itself is out of scope.
- The scanner lifecycle is tested for manual scan, discovery, handoff/reconnect and shutdown. Real OS port enumeration, driver quirks and actual attached hardware require separate explicit acceptance; periodic interval and failure-backoff wall-clock waits are configured but not tested against real hardware.
- A failed consumer transition intentionally remains suspended; an operator/recovery API for clearing that fail-closed state is not included.

This is a test-backed runtime foundation, not a completed or hardware-accepted migration.

## Supervisor round 1 remediation (HEAD `e9ef8d9`)

The aggregate supervisor report and its two independent reviews identified eleven blocking findings. All eleven received a scoped code change and regression evidence in this round:

| Finding | Repair/API | Regression evidence |
|---|---|---|
| 1. Cleanup ownership/shutdown false success | `OwnedPortTask::close(&mut self, deadline)` retains its `JoinHandle` on timeout. Scanner keeps unfinished owners in its port map, removes the generation fence before close, and does not enumerate/reopen while an owner remains. `DiscoveryHandle::shutdown(&mut self)` returns a retryable timeout and keeps its join handle; scanner stays alive until owners and reservations are released. `ResourceArbiter::shutdown` closes lease admission, cancels/neutralizes the active resource and leaves actuation suspended. `HardwareServiceHandle::shutdown` joins owned producers before arbiter shutdown. | `shutdown_timeout_retains_worker_and_can_be_retried_after_cleanup`; `shutdown_waits_for_firmware_reservation_release_and_remains_retryable`; `shutdown_cancels_active_lease_without_resuming_actuation` |
| 2. Overwritten/lost handoff reservations | `PortHandoff` fields are private and include a unique reservation id. A second handoff of a reserved port completes with Busy. Handoff and release each use operation IDs (`begin_handoff`/`wait_handoff`/`take_handoff_result`, `begin_release_handoff`/`release_result`/`take_release_result`), so caller wait cancellation cannot lose a committed reservation or release outcome. | `handoff_reservation_cannot_be_overwritten_and_timed_out_wait_is_recoverable`; `shutdown_waits_for_firmware_reservation_release_and_remains_retryable` |
| 3. Coalesced/incomplete discovery tail lost | `discover_owned` returns `DiscoveryResult { identity, decoder, trailing_messages, protocol_errors }`. The worker continues with the same decoder and dispatches all complete tail messages in order. | `discovery_returns_coalesced_and_partial_trailing_messages_to_port_owner`; service end-to-end input routing test |
| 4. Malformed frame kills recoverable stream | Worker emits `PortEvent::ProtocolError` for malformed/decode/overflow frames and continues `FrameDecoder` resynchronization through later valid messages. | `malformed_overflow_reports_error_and_worker_processes_resynchronized_input`; `discovery_retains_protocol_diagnostic_and_valid_frame_after_malformed_message` |
| 5. Writes not generation-fenced | Every `DiscoveryHandle::send_message` carries `expected_generation`; scanner and the receiving port worker each validate it before write dispatch. | Reconnect stale-write assertion in `runtime_is_inert_until_started_then_discovers_owned_port_and_joins_on_shutdown` |
| 6. Resolver/cache resurrection | Resolver and cache now store per-port `{generation, revoked, routes/values}` state. Terminal disconnect invalidation tombstones an equal generation; `begin_reconfiguration` is the separate same-generation path. Only a strictly newer generation can activate after disconnect. | `disconnect_tombstone_rejects_late_same_generation_route_replacement`; `newer_connection_generation_can_reactivate_after_disconnect_tombstone`; service disconnect/reconnect trace |
| 7. Detection not autonomous/owned/fenced | Detection baselines include generation, sessions can bind to a source, matching source loss clears the baseline and terminates the operation, terminal outcomes latch, and the owned timer invokes a terminal callback. Service `start_detection` publishes timeout/detection/source-loss results through its injected consumer. Registry capacity is 1024 combined sessions with explicit `reap_terminal`. | `owned_detection_times_out_autonomously_and_retains_terminal_success`; `source_loss_terminates_only_matching_detection_generation`; `service_publishes_autonomous_detection_timeout_from_owned_session` |
| 8. No outer discovery deadline | `discover_owned` applies the 10-second default deadline to settle, drain, request writes and response reads, and shrinks transport I/O timeout to the remaining budget through `SerialIo::set_timeout`. | `discovery_outer_deadline_bounds_a_port_that_never_stops_sending_noise` |
| 9. Calibration sample/result bounds incomplete | All retained min/sweep/max samples share a fixed cap independent of notification draining. Terminal success and repository failure are retained as `Option<Result<Calibration, SessionError>>`. Cancel/source-loss/overflow/complete states latch and cannot overwrite one another during shutdown or firmware takeover. | `draining_calibration_notifications_does_not_unbound_retained_analysis_samples`; `calibration_persistence_failure_is_retained_as_terminal_operation_result`; `calibration_persists_only_after_legacy_collection_steps_complete`; service firmware takeover test |
| 10. No runtime dispatcher/operation owner; unleased handoff | `HardwareService<T,R,C>` owns a single scanner, ordered bounded event dispatcher, resolver/cache/session registry, shared arbiter, injected `HardwareRepository` and `HardwareConsumers`. It routes current-generation inputs, sends configuration ACKs to one per-port serialized operation, persists before success publication, revokes routes/cache/sessions on source loss, owns detection/calibration, and exposes firmware handoff only through an active arbiter `LeaseToken` permit. The port scanner itself also requires the permit; no bare port-name handoff API remains. | `service_owns_discovery_routing_configuration_ack_and_disconnect_revocation`; `service_cancels_calibration_before_firmware_handoff_and_waits_for_fresh_reconnect_input`; `service_publishes_autonomous_detection_timeout_from_owned_session` |
| 11. Unbounded command/sample state | Runtime and per-port serial queues are bounded sync channels of 64 commands with immediate queue-full errors. Dispatcher has 4096 ordered event slots and blocks producers for lossless backpressure. Configuration ACK inbox is capped at 256. Calibration retained analysis plus notification state is capped at its configured capacity. Caller timeouts set cancellation flags for queued writes. | `blocked_write_applies_bounded_command_backpressure`; calibration overflow regressions |
