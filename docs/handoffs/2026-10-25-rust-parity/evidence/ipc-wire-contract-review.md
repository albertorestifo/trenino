# Desktop IPC wire contract audit — 2026-10-25

Read-only source audit of every command name invoked by `tauri/ui/src/bridge/client.ts` (101 distinct names, including snapshot/subscription plumbing), the 110 registered desktop handlers, their argument extraction, concrete return types, AppServices projections and generated DTOs. No source implementation edits were made during this audit. The root's native WebView configuration-create failure was treated as confirmed external evidence; I did not drive the native app or use physical hardware.

## Findings

1. **Important: all five preview commands use the wrong argument naming convention.** `runtime_preview.rs:35,44,54,73,90` use bare `#[tauri::command]`, while bridge `client.ts:419-423` supplies snake_case keys. The installed Tauri macro source (`tauri-macros` command/wrapper.rs, default `ArgumentCase::Camel` and key conversion at lines 500-503) confirms these handlers expect `inputId`, `autoDistribute`, `moduleId`, `formatString`, `sampleValue`, `valueA`, `valueB`. `calibrationCeiling`, `previewInput`, `previewNotchMapping`, and `previewDisplay` therefore reject native calls for missing required keys. `previewOutputCondition('gt', 10, null)` is subtler: `operator` decodes but the optional camelCase threshold keys are absent, so Rust receives `(Gt,None,None)` and reports an invalid condition. Unit mocks bypass extraction and conceal this. Required repair: explicit snake_case on all five handlers plus actual generated-handler dispatch tests, including optional thresholds.

2. **Important: explicit JSON null cannot clear existing nullable patch fields.** Top-level `Option<Option<T>>` arguments in `ui_update_configuration`, `ui_update_train`, `ui_update_lever`, `ui_update_notch`, `ui_update_output_binding`, and `ui_update_display_binding` decode both missing and JSON null to outer `None`. Tauri's actual `CommandItem::deserialize_option` (`tauri/src/ipc/command.rs:146-155`) delegates present JSON null to serde's None and also visits None for an absent key. Storage correctly treats outer None as “unchanged”, so a successful save silently preserves the old value. Concrete UI trigger: clear a nonempty configuration/train description and Save; ConfigurationEdit even optimistically shows the cleared description until reload, while persisted data remains. Output-condition changes send null thresholds; display name and exposed nullable patch methods have the same contract issue. **Executed actual AppServices + serde probe** `/tmp/trenino-ipc-null-probe.rs` using a disposable DB: `null -> None`; successful configuration update retained `Some("original")`. Evidence `tmp/ipc-null-probe.log`. Repair must preserve missing versus explicit null, not turn every omitted field into a clear.

3. **Important: clearing a button's release sequence keeps the old sequence live.** `ButtonBindingWizard.svelte:154-156` sends null for cleared keystroke/on/off sequence fields. Rust `ui_put_button_binding` receives Option values, and `AppServices::put_button_binding` (around app.rs:1537-1554) builds patches with `draft.off_sequence_id.map(Some)` (same for endpoint/keystroke/on sequence). Null therefore becomes “unchanged” on an existing binding. Concrete trigger: edit a latching sequence binding with an off sequence, choose no release sequence and Save; the previous sequence remains in the returned/persisted binding and can still execute on release. **Executed probe** using actual AppServices/storage reproduced preservation of `Some(EntityId(1))`. This requires presence-aware button update fields as well as fixing nested Option commands.

4. **Important: atomic lever Save publishes the wrong subscription payload outside the publishing macro.** `runtime_mapping.rs:113-115` directly sends `result.train_detail` under `Topic::Trains`; the app's train subscription and `ui_get_snapshot('trains')` expect `TrainSummaryView[]`, not `TrainDetailView`. Successful atomic mapping Save can replace the subscribed train collection with an object. The root's canonical publishing macro repair does not cover this direct call. Command response `LeverMappingCommit.train_detail` itself correctly promises detail and should remain detail; only the event must be canonical. Root was notified while its publication fix was in progress.

5. **Important: editing module metadata overwrites display parameters that are absent from the wire request.** UiBridge `updateI2cModule` and ConfigurationEdit.saveI2cModule send only id/name/module_chip/i2c_address. `ui_update_i2c_module` constructs fixed defaults for HT16K33 (brightness 8, four digits, seven segment, no dot, left aligned, no minimum) and AppServices replaces all module params. Trigger: open a migrated eight-digit/fourteen-segment module, rename it or change address, and Save. The saved detail has default params and subsequent display encoding uses them. Preserve existing params on metadata-only edit; creation defaults do not justify resetting an existing module. Source-established; no physical display operation performed.

6. **Minor: timeout error codes violate the UI-safe error union.** `vjoy_failure` uses `"timeout"` for ConfiguratorError::Timeout and `sequence_session_failure` uses it for SessionError::Deadline. Generated UiFailure and `client.ts:297` ERROR_CODES omit timeout. A native timeout error is discarded by normalizeIpcFailure and replaced with generic “Rust desktop service is not available yet”, losing the actionable message. Either use an existing supported code or update the generated error contract/normalizer consistently.

## Root fixes inspected during the audit

The original configuration-create mismatch was present at audit start: UiBridge promised `UiSnapshot<DeviceDetailView>`, while the handler returned `UiSnapshot<Vec<ConfigurationSummaryView>>`; ConfigurationEdit navigated using `result.value.value.config_id`, yielding undefined. The root has now added `AppServices::create_configuration_detail` and changed that command's response. Its publishing macro now obtains canonical topic snapshots independently from command result DTOs, resolving the generic hardware-child/train-detail event mismatch in macro-generated commands. This was source-inspected after the change; native re-execution remains the root's smoke test. Finding 4 is the additional non-macro publisher.

## Coverage and checked-compatible families

- All 101 bridge-invoked names are registered. Nine additional registered commands are not called by UiBridge: add/delete individual sequence command, individual notch CRUD, firmware_history, get_connected_devices, unbind_lever, set_lever_binding_enabled. This is inventory, not an assertion that all missing UI affordances are bugs.
- Settings/consent, configuration detail/list, train detail/list CRUD responses, input/output/matrix child detail responses, lever/notch full-save responses, sequence CRUD detail responses, script snapshots/log/manual-run results, binding snapshots, vJoy requested-state snapshots, firmware snapshots/upload IDs/cancel booleans, serial inventory/configuration-operation DTOs, explicit port/generation manual hardware controls, simulator status/explorer/value DTOs, mapping commit envelope and guided session snapshots were compared to their bridge declarations and actual serialized DTOs. No further concrete response-shape mismatch was found in these groups.
- Nested object payload names (`NotchInput`, sequence commands, mapping endpoints/notches/captures, guided calibration endpoints) use serde snake_case fields and match the bridge. Guided session enum values and result fields match; extra analysis fields are compatible with the structural TS view.
- Outside the preview family, bridge calls with multiword top-level keys use handlers/macros explicitly configured snake_case. Bare handlers elsewhere take no user args or a one-word `id`, so their default camelCase does not create the same mismatch.
- Runtime command responses are cast with `as T` in `createBridge.command`, so TS compile/tests alone do not validate them. Generated DTO declarations reduce drift in leaf types but do not prove command-to-DTO or topic-to-DTO pairing.

No full test suite was rerun for the audit. Executed evidence is restricted to the disposable actual-source null/button persistence probe and command-registration inventory; native preview dispatch is established from installed macro/extractor source, not claimed as a WebView execution.

Existing UI guards cover many of these; no separate native failure was established. Root corrected the eight overrides and regenerated declarations during the follow-up.
