# Desktop nullable IPC and I2C repair review

Read-only scoped review of `tmp/ipc-wire-contract-review.md`, `tmp/ipc-null-patch-implementation.md`, actual `wire_patch.rs`/Tauri command handlers, AppServices and storage paths. The owner reports 30 desktop library tests (seven actual generated-handler invocations) and 77 focused runtime tests passing; no unchanged suites were rerun. UI screens and the separate whole-branch review are outside this scope.

## Original audit finding disposition

1. **ADDRESSED — preview argument casing.** All five preview handlers now declare `rename_all = "snake_case"`; the root reports actual handler invocation for their multiword arguments. `ui_preview_output_condition` receives optional thresholds under the bridge's keys.
2. **ADDRESSED — missing versus explicit null for top-level patches.** `wire_patch.rs:7-28` reads the actual JSON InvokeBody key and preserves omitted `None`, explicit null `Some(None)`, and a validated supplied value `Some(Some(T))`. Every formerly nested-option desktop patch family listed in the audit uses `NullableArg`: configuration/train description, lever optional endpoints/type, all nullable notch numerics, output thresholds and display name. Actual `MockRuntime` handler tests exercise omission and null through storage.
3. **ADDRESSED — stale button release sequence.** `rust_ui.rs:2690-2705` uses presence-aware endpoint/keystroke/on/off-sequence fields; `app.rs:1548-1600` forwards the precise patch. The actual handler test clears a persisted off sequence, and the runtime regression checks that a release no longer executes its old simulator PATCH after reload.
4. **ADDRESSED — canonical train publication after atomic mapping save.** `runtime_mapping.rs:106-124` publishes the canonical train-list and bindings snapshots returned by the guarded save, while retaining detail/validation in the command response. The generic publishing macro separately obtains `snapshot_json(topic)` for canonical events (`rust_ui.rs:1974-2008`), so detail command results no longer replace list subscription payloads.
5. **ADDRESSED for serial edits — I2C metadata no longer resets absent params.** `rust_ui.rs:2171-2196` treats absent/null params as preserve on update and converts a supplied full object, including `min_value:null`; `app.rs:1079-1110` retains the current params when absent. Creation uses the legacy brightness 8, four digits, fourteen segment, right alignment, minimum 0.0 defaults. Actual handler tests cover migrated eight-digit preservation, explicit replacement, null minimum, defaults and validation. A concurrent-edit race remains below.
6. **ADDRESSED — timeout error union.** The configurator and manual-sequence timeout paths now use the supported `unavailable` UiFailure code while retaining their specific messages and retryability. The generated nullable TypeScript declarations were also corrected and exported.

The desktop train-delete command checks the live control runtime and active train before mutation, rejecting unavailable runtime or an already active matching ID. The implementation explicitly does not provide an atomic detection/DB gate; a train can become active after the snapshot check. This is a remaining concurrency limit of the new guard, not counted again as one of the six original audit findings.

## Important finding

**Metadata-only I2C edits can roll back a concurrent full-parameter edit.** `AppServices::update_i2c_module` obtains `current.params` from `hardware_snapshot()` (`app.rs:1089-1100`), then calls `db.update_i2c_module` with `params.or_else(|| current.params.clone())` (`:1100-1110`). Those are separate requests on the single DB worker. Interleaving: editor B begins a name/address-only update and reads eight-digit params; editor A commits an explicit new brightness/digit/display configuration; B's later update writes its stale snapshot through `hardware.rs:1142-1155`, returning success and reverting A's parameter edit even though B omitted `params`. The implementation promise that an absent param object preserves *the existing value at commit* is therefore only true without concurrent writers. **Targeted test:** pause B after its snapshot, commit A's explicit params, resume B, and assert A's params survive while B's metadata changes. Resolve omitted params from the current row inside the same `hardware_tx` transaction as the metadata write, or use a revision compare-and-retry guard.

## Quality note

`mutation_publication` intentionally returns the committed command result if its subsequent canonical snapshot read fails (`rust_ui.rs:1981-1987`), avoiding a false rollback error. It also emits no change event in that case (`:2000-2008`), so an already subscribed second window can remain stale until another publication. The current tests prove the healthy canonical payload; a fault-injected post-commit snapshot failure should verify either a queued retry/invalidation or an explicit refresh signal. This is not counted as a separate Important finding because no recoverable failure sequence was demonstrated in this review.
