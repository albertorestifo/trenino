# Guided sessions, atomic lever mapping and Rust distribution review

Read-only review of the three implementation handoffs and scoped production source. The reported guided-session 11, simulator-detection 31, runtime-lib 20, atomic-mapping/domain, desktop 20, and build-config 3 tests pass; the parent also reports a serial 804-test workspace and strict all-target clippy pass. No physical simulator, serial hardware, installer or packaged app was run. UI screens are in progress and excluded.

## Verdict

**Guided session spec/quality:** The one-slot host uses only the accepted connection client, serializes subscription 99 with lever moves and manual sequences, joins cancelled workers, retains failed unsubscribe cleanup, and gives sequence success only after every PATCH succeeds. **Not integration-ready** until the closed-watch and abandoned-start paths are fixed.

**Atomic mapping spec/quality:** The core save reloads the input/calibration, derives normalized ranges inside one SQLite transaction, applies binding exclusivity, replaces notches and advances train/binding revisions. The injected final-insert rollback test is meaningful. **The guided calibration save and desktop acknowledgement need fixes** below.

**Distribution spec/quality:** The explicit Rust branch skips BEAM and the legacy vJoy sidecar, and avrdude probes the executable sibling with bundled config in resource storage. The CLI overlays match the build context. **Packaged keyboard discovery and clean non-Windows staging remain broken** below.

## Important findings

1. **A closed connection watch spins in the biased branch and prevents session shutdown.** `composition/sessions.rs:261-269` sets `closing=true` when `status.changed()` returns `Err`, but leaves that permanently-ready future in the first branch of `tokio::select! { biased; ... }`. The actor then loops without an await and cannot service queued `Status`, `Cancel` or `Shutdown` commands; `finished` is never set. If the last snapshot still says Connected with the same client, the active worker is not cancelled either. This happens if the connection owner exits unexpectedly while the control runtime retains the session host. **Test:** start the host from a watch channel, drop the sender, then call `shutdown` under a bounded timeout on a multithread runtime; require prompt acknowledgement, active cleanup and no spinning worker. Disable the watch branch after closure and cancel/join any active session once, then continue draining commands or terminate with `Closed`.

2. **A start request can time out and later create an orphaned active session.** `SimulatorSessionHost::request` enqueues `Start` and times out the reply after seven seconds (`sessions.rs:162-176`). The actor's `Start` branch (`:273-276`) never checks whether that oneshot receiver is still alive before inserting the snapshot and spawning detection/analysis/calibration. A series of held failed-unsubscribe cleanups can keep the actor busy past seven seconds; after cleanup finally succeeds, the caller has a `Deadline` error but a later `Start` begins simulator subscriptions or lever writes and occupies the only slot with an ID no caller received. **Test:** queue a start behind three cancellation cleanup attempts that each reach their three-second deadline, let its request deadline elapse, then make cleanup succeed; assert subscription 99 and lever PATCH count do not increase and the slot stays free. Fence expired/closed requests before work starts, or attach a deadline to the command and clean up immediately if reply delivery fails. The queued `RunSequence` branch should likewise check its dropped receiver before initiating PATCH writes.

3. **Atomic commit does not mark a completed simulator lever calibration.** The guided calibration session returns a `CompletedCalibration` draft for later atomic save (`composition/sessions.rs:320-353`), and that save replaces notches in `storage/domain/trains.rs:1694-1703`. Unlike the retained `save_calibration` path (`trains.rs:1195-1207`) and the Elixir `Train.save_calibration/2` oracle (`lib/trenino/train.ex:350-367`), the new config creation/update at `:1685-1693` never sets `calibrated_at`. Thus a wizard that completes calibration and saves all notches still has `calibrated_at = NULL` (or the previous timestamp), so persisted completion metadata is wrong. **Test:** obtain a calibration draft, commit it through `ui_commit_lever_mapping`, and assert the returned/persisted config has a new `calibrated_at`; keep manual notch-only saves on their legacy no-timestamp path. The API needs a trusted or explicit calibration-save mode so the two cases remain distinct.

4. **The desktop mapping command can return an error after a successful atomic commit.** `runtime_mapping.rs:94-103` commits and obtains both returned train detail and validation, publishes the train change, then performs a separate fallible `state.services()?.get_bindings_snapshot()` before returning `Ok`. If shutdown admission or that read fails in this gap, the mapping is committed and the train event is published, but IPC reports failure. A retry using the same `lever_config_id` can then conflict with the newly committed config. **Test:** arrange shutdown or a fault-injected bindings-snapshot read immediately after the transaction, call `ui_commit_lever_mapping`, and require a committed acknowledgement with both topic publications, or an explicit uncertain result that tells the caller to refresh. Build the binding snapshot while the same guarded operation is still owned, and do not turn a post-commit publication failure into an apparent rollback.

5. **Packaged macOS/Linux keystroke mappings cannot find the bundled sidecar.** `rust_ui.rs:293-294` points `ExecutableProbe::keystroke` at `app.path().resource_dir()`, and `executable.rs:145-155` resolves only `resource_dir/keystroke` in release. Tauri's `externalBin` sidecar lookup resolves beside the main executable (local `tauri-plugin-shell-2.4.0/src/process/mod.rs:120-155`), while Tauri's resource directory is `Contents/Resources` on macOS and `usr/lib/<app>` in Linux AppImage (local `tauri-2.12.1/src/path/desktop.rs:213-230`). The overlay bundles keystroke as `externalBin`; `OptionalKeyboard` therefore stores discovery failure and every native key action fails in installed macOS/Linux builds. Windows resource dir equals executable dir and is unaffected. **Test:** create distinct fake executable/resource directories matching each packaged layout, place keystroke only beside the executable, construct the production probe, and require discovery. Point the keystroke probe at the installed executable sibling as avrdude already does. Root reported this correction in progress during review; this finding describes the inspected original source.

6. **The Rust wrapper cannot build a clean non-Windows bundle.** `scripts/build-desktop.sh:85-89` stages `avrdude-$PLATFORM` plus `avrdude.conf` only on Windows, while the Rust CLI overlay (`tauri.rust.conf.json`) requires `binaries/avrdude` as `externalBin` and `binaries/avrdude.conf` as a resource for macOS and Linux too. Neither file is tracked in this checkout. `scripts/build-rust-desktop.sh` merely enters this script; on a clean Mac/Linux checkout it reaches `cargo tauri build` without either required staged file and bundle validation fails. **Test:** run the Rust build wrapper in a clean disposable checkout through the staging/preflight phase on macOS/Linux and assert both target-suffixed avrdude and config exist before invoking Tauri. Stage compatible verified artifacts or make the wrapper fail early with a precise prerequisite diagnostic; the current handoff explicitly acknowledges this unfinished distribution input.

## Scoped composition round-3 disposition

The two Important findings in `tmp/composition-lifecycle-fix2-review.md` are **addressed in current source**. `HardwareRuntime::neutralize_and_release_outputs` now calls the effect ledger's bounded `neutralize_all` before serial close (`rust_ui.rs:1202-1204`), including manual/script targets and retaining failed cleanup (`composition/hardware.rs:195-240`). `HardwareRuntime::close_ports_and_network` borrows its handle mutably and takes it only after `close()` succeeds (`rust_ui.rs:1206-1213`), preserving failed serial owners for retry. The parent reports seven effect and 19 desktop focused tests green. No new defect was established in these two fix paths.
