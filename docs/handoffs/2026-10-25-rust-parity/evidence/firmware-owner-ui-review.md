## Verdict

The original missing-production-callers finding is addressed: desktop startup owns the scheduler, automatic checks publish committed snapshots, and the global notice/dismiss workflow is reachable. **One Important parity regression remains: explicit manual checks incorrectly obey the automatic cooldown, preventing immediate retry after a failed check.** No Critical finding. ## Important — manual Check returns success without retrying for an hour

`crates/trenino-runtime/src/firmware/owner.rs:232-238` handles an explicit `Command::Check` through `scheduler.begin_check(now())`, the same persisted one-hour gate used by automatic ticks. A recent result, including an HTTP failure, therefore returns `Ok(())` without invoking the check port. The desktop command at `tauri/src-tauri/src/rust_ui.rs:2949-2960` consequently returns a successful stored Firmware snapshot. Changing the UI feedback to “Showing saved firmware releases” avoids a false freshness claim but does not preserve the retained manual retry action.

The actual oracle explicitly bypasses this limit for manual requests: `lib/trenino/firmware/update_checker.ex:192-193` calls `maybe_perform_check(state, true)`, and `:265-267` uses `force || should_check?(state)`. The Firmware page independently calls `Firmware.check_for_updates()` directly (`lib/trenino_web/live/firmware_live.ex:152-155`). The initial one-hour limit is for automatic checks; a manual retry after connectivity recovers must still attempt a refresh. Both the new owner test and generated-handler test currently encode suppression of a second sequential manual check, so their green result does not establish oracle parity.

**Executed RED:** `/tmp/trenino-firmware-manual-review.rs`, `review_manual_retry_must_refresh_after_a_failed_automatic_check`, links the actual runtime and reuses the checked-in owner fake ports. Advance FakeClock five seconds, let the automatic check persist `offline`, recover the fake upstream, immediately call `owner.check()`. Actual: `Ok(())`, refresh count remains **1**, and status still contains `error_message: Some("offline")`. Expected: count **2**, refreshed result and no stale error. The owner is shut down/joined before the assertion. No real network request occurs.

Keep the automatic persisted cooldown and existing active-check coalescing. Explicit manual admission should bypass the cooldown while still joining an already running check and obeying queue/owner limits. Add a regression for immediate retry after a failed automatic check and retain restart-rate-limit coverage on the automatic timer rather than on a forced manual command.

## Verified production integration and lifecycle

- `rust_ui.rs::wire_runtime_services` constructs the real catalog/repository on the shared Database worker, starts `FirmwareUpdateOwner`, stores its handle and registers `FirmwareParticipant`. The scheduler defaults are five-second startup, 24-hour cadence and one-hour automatic minimum. The owner uses the injected clock plus epoch anchor; it owns its timer, HTTP future and bounded command/waiter collections. Concurrent manual requests join the active check rather than making duplicate requests.
- `DbFirmwareRepository::latest_check` now uses the timestamp parser in `runtime_firmware.rs`, accepting current ISO-Z and legacy SQLite/Ecto UTC values and fractional seconds. Its source checks calendar validity, time ranges and fractional syntax. The existing actual-DB desktop test covers the exact one-hour boundary; that desktop test was inspected rather than rerun here.
- Refresh completion persists the check record before invoking the canonical Firmware publication callback. HTTP errors are recorded and returned; persistence errors remain visible without claiming a committed check. The observer holds a Weak AppServices reference and publishes `get_firmware_snapshot()`, avoiding a strong ownership cycle.
- Stop admission signals cancellation before producer cleanup. The owned HTTP future is dropped before host exit. Shutdown joins the actual thread; blocked synchronous persistence causes a bounded error with the same join handle retained, and a host panic remains a sticky failure. The registered participant runs before the application's database-close phase. Cancellation cannot interrupt a synchronous DB call, and the implementation correctly requires a retry instead of falsely acknowledging closure.
- Inventory comes from `HardwareCommandPort.connected_ports()` and the actual observed identity version. Configured ports contribute their real EntityId; unconfigured boards contribute their real port name without synthesized IDs. Scheduler-side version comparisons filter connected/outdated known versions, sort/deduplicate recipient sets and persist dismissal keys. A different outdated set or version can show a notice again. Root's discovery field test is separate evidence, not rerun here.
- `App.svelte` polls after the consent gate opens and every two seconds. Sequence/mount guards reject stale or post-unmount replies. Failed reads retain the last known notice and show an error. Dismiss invalidates older polls, suppresses polling while pending and changes the displayed notice only on the backend reply; failed persistence keeps the notice/error visible. Navigation links to Firmware and exposes manual checking/error state. The page consumes the same owner status and canonical Firmware subscription, and refreshes its catalog when the persisted check timestamp changes.
